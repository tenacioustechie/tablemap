# ADR 0021: Map rotation as a scene operation, separate from the player view's rotation

Status: accepted (T017)

## Context
Maps get scanned or exported sideways. Before T017 the only way to turn one was the player view's rotation (ADR 0014), which turns the *presentation*: the TV faces one way, the map on the DM canvas stays sideways, and a second map in the same campaign that was scanned the right way up is then wrong on the TV. ADR 0014 rejected rotating the image inside the player transform because fog, tokens and annotations are all in map pixels and would fall out of step. `docs/plans/2026-09-dm-usability.md` §3.3 has the review.

## Decision
- **Rotation is a document operation on the scene, in quarter turns.** `map/rotate { id, degrees: 90 | 180 | 270, fogMaskAssetId }` is applied by the pure `rotateScene` (`state/sceneRotation.ts`) in the shared reducer, so both windows keep seeing one consistent coordinate space: the scene's `width` / `height` swap for a quarter turn, `imageRotation` advances, and the grid origin, every token, every note and drawing point and every fog op in the log are turned by the same point transform (90°: `(x, y) ↦ (H − y, x)` for the old size `(W, H)`; 180°: `(W − x, H − y)`; 270°: `(y, W − x)`). Four quarter turns are the identity, coordinate for coordinate. The player view's TV rotation stays what it was: a presentation-only quarter turn composed on top, with its own control and its own labels.
- **The image asset is never re-encoded.** Schema v8 adds `MapScene.imageRotation` (0 | 90 | 180 | 270): how far the stored asset is drawn turned. `MapStage` draws the image node at the asset's own size, rotated, at the position (`rotatedImagePlacement`) that makes it cover `[0, width] × [0, height]` of the turned scene. Re-encoding would cost a lossy round trip for JPEG maps, a canvas the size of the whole image in memory (8k-pixel scans exist) and a second copy of the asset on disk; a rotated draw costs nothing and is exact for quarter turns. v7 documents migrate with `imageRotation: 0`; the field travels in `campaign.json` and the assets in an export are unchanged.
- **The base fog mask is baked turned, like a compaction.** The mask is a bitmap, so the DM side (`mapActions.rotate`) draws it turned onto a canvas of the turned size (`map/fogMask.ts: rotateFogMask`, using the same placement maths as the stage so mask and image pixels turn together, pixel for pixel), stores it as a new `fog-mask` asset, dispatches the op with the new id, and deletes the old asset once nothing references it — the choreography of `map/fog-compact`. A compaction landing during the bake aborts the turn (nothing is written; the next click retries). A map without a base needs no bake and no open campaign.
- **Undo keeps working; redo is cleared.** The log's ops are turned in place, so `map/fog-undo` still drops the right op and the mask rebuilds correctly; `fogOpsFrom` is untouched. The DM-only redo stack holds ops undone *before* the turn, in the old coordinates; re-applying one would reveal the wrong place, so `fogHistory` drops that map's stack on a `map/rotate`. Rejected: turning the redo stack too — it would work, but the stack is not part of the document, and every other editor-wide change (a new op) already discards it; keeping the rule simple is worth more than the rare redo after a rotation.
- **The pan centre is dropped, the DM canvas refits, the fog canvases rebuild.** A `map/rotate` on the active map clears `presentation.center` in the same store commit (`presentationForMapRotate`, like a scene switch but without raising the splash): the centre's coordinates belonged to the map the old way round. `DmCanvas` refits when the scene's size changes, not only its id. Both stages' fog rasters resize on a size change (`createFogMaskUpdater` already did; verified), so the player briefly shows the turned map fully fogged until the turned base PNG arrives, then rebuilds — the safe side, as with a fresh player window.

## Consequences
- Schema bump to 8 (migration adds `imageRotation: 0`); one new shared op; `state/sceneRotation.ts` is the single place that knows how a scene turns, shared by both windows.
- The Maps tab's Grid section gains **Map rotation** ⟲ / ⟳ with the current value (`map-rotate-ccw` / `map-rotate-cw` / `map-rotation-value`, aria-labels "Rotate map counter-clockwise / clockwise"), disabled while a bake is in flight; any armed tool is put down first (its gesture would be in the old coordinates). The user guide explains which rotation to use when: the map's for a sideways scan, the player view's for which way the TV faces.
- The stage draws the image with a rotation for the first time; `MapStage.test.tsx` pins the node's rotation, position and client box per value, and `e2e/rotation.spec.ts` checks real pixels on both windows, including a mask baked on a real canvas after a compaction.
