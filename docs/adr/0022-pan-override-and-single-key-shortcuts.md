# ADR 0022: Pan override while a tool is armed, and single-key shortcuts from one table

Status: accepted (T018). Amends ADR 0020 (the tool status chip now shows the armed tool's key). Amended by ADR 0024 (T101: the tab keys run `1`–`6`, with `5` the new Walls tab and `6` Table).

## Context
With a fog tool, the pen or the note tool armed, the DM canvas gave every left-button press to the tool and turned Konva's drag-pan off (`MapStage`: `draggable={interactive && !pointerTool}`), so revealing a map larger than the screen meant Esc, drag, re-arm, over and over (`docs/plans/2026-09-dm-usability.md` §1, item 3). Every tool, mode and tab was also mouse-only except Esc and fog undo / redo (item 4). Wheel zoom already worked under any tool.

## Decision
- **A pan override, done by the stage, not by juggling the tool.** A middle-button press, or any press while Space is held, pans the DM canvas whatever tool is armed. `MapStage` gains a `panOverride` prop and a middle-button rule; on such a press it records the pointer and the viewport, follows the pointer through *window* listeners (the pan survives leaving the stage) reporting `start + offset` through `onViewportChange`, and withholds the tool's `onDown` / `onMove` / `onUp` until the release. Rejected: swapping the tool out (`pointerTool = undefined`) while Space is held so Konva's own drag takes over — it works for Space but not for the middle button (Konva's `dragButtons` is global state, and the tool must be unset *before* the press), it re-enables the tokens and handles beneath, and it drops the tool's hint and cursor mid-gesture; and intercepting presses in `DmCanvas`'s wrapper with a capture-phase `stopPropagation` — it relies on React's root listener firing before Konva's content listener, an ordering nothing guarantees. The stage already owns the pointer dispatch and the "interactive" idea; the player never sets `interactive`, so it is untouched.
- **Space is a modifier the canvas watches, not a shortcut.** `DmCanvas` tracks Space on the window (outside editable targets; released on `blur`), shows the `grab` cursor, and while it is down withholds the token tool, the player-viewport handle and the note markers' draggability so the pan wins over every draggable thing. Space's default is suppressed only while the pointer is over the canvas: the common flow is "click Brush, move onto the map, hold Space" — the Brush button still has focus and would toggle itself off on the key's release. Over the sidebar the key keeps its meaning (Space activates the focused control), so keyboard users lose nothing.
- **One pure table, `dm/shortcuts.ts`, is the keymap, the cheat sheet, the chip's hint and the user guide's table.** `SHORTCUTS` lists every key with its label and command; `shortcutFor(event)` is the only place a keydown is interpreted (no Ctrl / Cmd / Alt; Shift only for `?`; nothing from an editable target — the same `isEditableTarget` the undo / redo listener uses); `shortcutKeyFor(command)` gives the chip its key; the `?` overlay renders the table; `docs.test.ts` checks the user guide's keyboard table against it. Keys **arm** a tool, never toggle it: a DM hammering `B` to make sure the brush is ready must not turn it off; `V` and Esc put tools down. A fog or draw key opens the owning tab so the panel shows what the key changed. `[` / `]` change a setting only and open nothing. Tool keys need an active map, like the buttons. Rejected: a per-panel `onKeyDown` (keys must work with the panel unmounted on another tab, ADR 0020), and reusing the panels' toggling `selectFogTool` / `selectDrawMode` for the keys.
- **Esc closes the cheat sheet and nothing else.** The tools' Esc listeners live on the window (`DmCanvas`); while the sheet is open `DmView` registers a capture-phase keydown listener on the *document*, which fires before any window bubble listener for every real key event (whose target is an element) and stops the event there. Other shortcuts are ignored while the sheet is open. Rejected: threading a "help open" flag into every tool effect, and relying on the sheet's own focus (it is focused on open, but a click elsewhere would move focus and hand Esc to the tools).

## Consequences
- `StagePointerTool` is unchanged; `MapStage` gains `panOverride`, `PAN_MOUSE_BUTTON` and `data-panning`; `DmCanvas` reports `data-pan-override`; `describeTool` returns a `key`; `FOG_BRUSH_RADIUS` gains `step` and `stepBrushRadius`. No store, protocol, schema or player change.
- A middle-button press no longer autoscrolls the page on Windows / Linux over the canvas (it is `preventDefault`ed to pan instead). Touch has no pan override: the middle button and Space are mouse and keyboard notions; touch users keep Esc.
- Keys are letters and punctuation without modifiers, so they only work outside text fields — which is why the campaign name, the note textarea and every slider swallow them. Non-US layouts where `?` is unshifted work too (`?` is matched by `key`, Shift or not); layouts where `[` / `]` need a modifier lose those two keys, and the slider remains.
- The user guide's keyboard table must list every shortcut with its exact label, in order, or `docs.test.ts` fails — the table is regenerated by hand from `SHORTCUTS` whenever the keymap changes.
