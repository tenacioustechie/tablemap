# ADR 0029: Desktop installers with Electron; CI builds, tests and releases them

Status: accepted. Amended by ADR 0031 (auto-update from the same releases). Builds on ADR 0001 (local-first web app): the web app is unchanged and still runs in a browser; the desktop app is a second way to ship the same `dist/`.

## Context
TableMap is being open-sourced for a group of players who want to download and install it on Windows and macOS rather than clone a repository and run `npm run dev`. The app is a static SPA with no backend; it depends on three browser features the shell must keep working: IndexedDB (campaigns, ADR 0007), BroadcastChannel between the DM window and the player window (ADR 0003), and `window.open` with a live handle to that window (ADR 0005).

## Decision
- **Electron** (`electron`, `electron-builder`, dev dependencies only). It embeds Chromium — the engine the Playwright suite already tests — so all three features behave exactly as in the tested browser, on both platforms. Rejected: Tauri — it uses WebKit on macOS and WebView2 on Windows, so DM↔player BroadcastChannel and `window.open` between two webviews would be new, untested ground on each platform, for a smaller download. Rejected: a PWA install — no downloadable installer, and the player window is a popup the install would not own.
- **A thin shell, no Node in the page.** `app/electron/main.mjs` serves `dist/` from a privileged custom scheme, `app://tablemap` (`electron/appPaths.mjs`: `resolveAppFile` maps a request onto `dist/` and refuses anything outside it), because `file://` gives an opaque origin that IndexedDB and BroadcastChannel cannot rely on. Windows are sandboxed with context isolation and no preload or IPC. `window.open` of an app URL (the player view) is allowed as a second native window with its menu bar hidden; any other link goes to the system browser, and navigation away from the app is refused. One instance at a time. Campaign export uses the normal download path, which Electron answers with a native Save dialog.
- **Packaging** (`package.json` → `build`): macOS DMGs for Apple silicon and Intel, a Windows NSIS installer (per-user, directory selectable), output in `app/release/` (git-ignored). There is no paid Apple or Microsoft signing identity, so the mac build is **ad-hoc signed** with hardened runtime and `build/entitlements.mac.plist` (`disable-library-validation`, without which an ad-hoc signed Electron app does not launch), and both platforms show a first-launch warning the release notes explain (`.github/release-notes.md`). Real signing can be added later through electron-builder's `CSC_*` secrets without changing the shell.
- **CI** (`.github/workflows/ci.yml`): every push and pull request runs the gates (typecheck, lint, unit, e2e) on Linux, then packages the app on `windows-latest` and `macos-latest` and runs `scripts/desktop-smoke.mjs` against each *packaged* app (Playwright's Electron driver: loads from `app://tablemap`, DM view mounts, IndexedDB is there, the player window opens and receives sync). The installers are attached to the run. A `v*` tag additionally versions the build from the tag and publishes a GitHub Release with the installers, using the runner's `gh` CLI (no third-party release action).

## Consequences
- Two new dev dependencies; nothing new at runtime in the page. The packaged app is ~130 MB, mostly Chromium.
- Electron's production `node_modules` copy of the web app's runtime dependencies rides along in the asar unused (Vite has already bundled them); harmless, and avoids restructuring `package.json`.
- Auto-update was added by ADR 0031. Campaigns live in the desktop app's own storage, separate from any browser's; Export / Import moves them.
