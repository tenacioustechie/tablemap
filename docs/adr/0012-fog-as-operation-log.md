# ADR 0012: Fog of war as a base PNG plus an operation log — schema v4, `map/fog-op`, `map/fog-compact`

Status: accepted (T007)

## Context
Fog is a per-map alpha mask the size of the map image: black where the players may not look. The DM edits it many times per session (brush strokes at 60 fps in T008), the player window must show every change within 100 ms, the state must persist and export with the campaign, undo needs a history, and the player is a render-only mirror that never reads storage (ADR 0003, ADR 0007). Sending the mask as pixels on every change is out: a 4000 × 4000 mask is 16 MB raw and hundreds of kilobytes as PNG, far too slow to encode per stroke and pointless to persist per stroke.

## Decision
- **The mask is described, not shipped.** A map's fog is `fogMaskAssetId` — the *base*, a PNG `fog-mask` asset (ADR 0007) the mask starts from, null meaning fully fogged — plus `fogOps`, an ordered log of `FogOp`s (`state/fog.ts`) applied on top. Both windows rasterise base + log with the same code and get the same pixels; "pixel-identical" is by construction, and `map/fogRaster.test.ts` / `syncDrivers.test.ts` check it on a bitmap raster.
- **Ops are plain JSON in map pixels.** `{ type: "fill", mode }` (hide all / reveal all) and `{ type: "shape", mode, shape }` with `mode` `reveal` | `hide` and `shape` a `rect`, `circle` or `polygon`. Rectangle is the only tool in T007; the other shapes are rasterised already so T008's brush and lasso are UI only. Feathering, when it arrives, is an optional per-op field (no migration needed).
- **One shared op appends, one compacts.** `map/fog-op { id, op }` appends to a map's log. `map/fog-compact { id, baseAssetId, opCount }` says the first `opCount` ops are now baked into `baseAssetId`: the reducer swaps the base, drops those ops and advances `fogOpsFrom`. Both are ordinary sequenced ops, so the player, the autosaver and (later) export see fog like everything else. `SCHEMA_VERSION` is 4; v3 documents gain `fogOps: []`, `fogOpsFrom: 0`.
- **`fogOpsFrom` is the history index of `fogOps[0]`** — how many ops of this map's lifetime precede the log. A renderer remembers the history index it has applied up to, so after a compaction (log shorter, base different) it still knows exactly which entries are new. Without it a renderer would have to guess by matching op contents, or rebuild.
- **Compaction is the DM's job and never changes pixels** (`state/fogActions.ts`). When a log reaches `FOG_COMPACT_AT` (64) entries, the DM bakes base + the first `length − FOG_KEEP_OPS` (32 kept, so undo will have ≥ 20 steps) ops into a PNG on a canvas (`map/fogMask.ts: bakeFogMask`), stores it as a `fog-mask` asset owned by the campaign, and dispatches `map/fog-compact`. After every await it re-checks that the baked prefix is still the live log's prefix (op identity, base id, `fogOpsFrom`); a log rewritten meanwhile aborts the compaction and the next op retries. The previous base is deleted once nothing references it (a duplicate copies the base under its own id, ADR 0007). The PNG reaches the player like a map image, as an `asset` message (ADR 0008).
- **Rendering** (`map/fogRaster.ts`, `map/fogMask.ts`, `map/useFogMask.ts`): each stage owns one offscreen canvas the size of the map. `hide` paints black with `source-over`; `reveal` punches through with `destination-out`. A `FogMaskUpdater` keeps the canvas in step with the scene: *incremental* (same map, same base, log grown → apply only the new ops), *rebuild* (anything else, with the base at hand), *bridged* (base changed by compaction but its PNG not received/decoded yet: the canvas already shows the right pixels, so keep it, apply new ops, rebuild when the PNG lands — no black flash on the TV mid-compaction), *waiting* (a base this window has never had: fully fogged until it arrives — the safe default). The stage draws the canvas as the top layer at `FOG_ALPHA.dm` = 0.5 for the DM, 1 for the player. A `Uint8Array` raster implements the same operations arithmetically (pixel centres, even-odd polygons) so the op maths is unit-tested without a canvas and can answer "is this cell fogged?" for tokens (T010).
- **Latency**: a reveal is one `delta` on the BroadcastChannel and one `fillRect` on the player's mask; `e2e/fog.spec.ts` measures DM click → player fog repaint (`Date.now()` in both windows) against 100 ms (1 s under `CI`).

## Alternatives considered
- **Op log only, no PNG.** Simplest, but unbounded: a session of brush strokes grows the document, every snapshot and every rebuild without limit. The PNG bounds all three.
- **PNG only, written after every change** (debounced), ops sent to the player as deltas without being persisted. Bounded, but a player joining mid-session would need the bitmap (fine, it is an asset) *and* the ops since it was written — the same two-part state, just with a race between them, and no history for undo.
- **Fog in DM-only state, pushing the whole mask as an asset on change.** Bitmaps over the channel per change; rejected by the task and by the 100 ms budget.
- **A `fog/hide-all` reset op that clears base and log.** Cheaper than a `fill` op that stays in the log, but it destroys history; `fill` is one entry and compaction folds it away anyway.

## Consequences
- Documents written by this build are refused by T006 builds (`newer-schema`); older documents migrate on load. Every `MapScene` literal needs `fogOps`/`fogOpsFrom`.
- `MapStage` always has a fog layer (one more canvas per stage); tests counting canvases changed accordingly.
- Baking runs on the main thread; at 64 ops per bake and typical map sizes it is a few tens of milliseconds. T008 should batch a brush stroke into one polyline/polygon op rather than one op per pointer move so compaction stays rare; if that proves insufficient, baking can move to a worker with `OffscreenCanvas` without changing the protocol.
- Undo (T008) can pop ops off the log; the updater already rebuilds when the log shrinks, and compaction aborts if its prefix changed. Undo across a compaction boundary is not possible by design — that is what `FOG_KEEP_OPS` guarantees a margin for.
- Mask memory is map-sized per stage (width × height × 4 bytes on the canvas). Very large images (> 8k on a side) would want a downscaled mask; not needed for v1.
