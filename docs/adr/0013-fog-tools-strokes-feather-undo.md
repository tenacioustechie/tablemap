# ADR 0013: Fog tools — stroke and cell-union shapes, feather as a per-op field, undo as a shared op, gestures committed on release — schema v5

Status: accepted (T008)

## Context
T007 (ADR 0012) made fog a base PNG plus an op log of `rect` / `circle` / `polygon` shapes, rasterised identically in both windows. T008 adds the tools the spec asks for: a brush with an adjustable radius, a rectangle, a polygon lasso, each in reveal or hide mode, feathered edges (default on), a grid-snap mode painting whole cells, and undo/redo of at least 20 steps that the player window follows. The brush must drag at 60 fps on a 4k-pixel-wide map, and the TV must still show a reveal within 100 ms of the DM's action.

## Decision
- **Two new shapes, one optional field, no data migration.** `stroke` (`{ points, radius }`: a polyline with round caps and joins, i.e. the union of capsules; one point is a disc) is what a brush drag becomes — one op per stroke, not one per pointer move. `rects` (`{ rects: [x, y, w, h, ...] }`, a union of rectangles) is what grid snapping produces, so a snapped gesture is still one op whatever the cells. A shape op may carry `feather` (soft-edge width in map px), as ADR 0012 anticipated. `SCHEMA_VERSION` becomes 5 with an identity migration step: a v4 document is a valid v5 document, but a v4 build must refuse a v5 document as `newer-schema` instead of reporting the new shapes as invalid.
- **Feather is rendered as the shape's own blurred shadow.** The canvas raster draws a feathered shape `SHADOW_SHIFT` px off the surface with `shadowOffsetX` bringing the shadow (`shadowBlur = feather`) back into place. This works with both `source-over` and `destination-out` in every engine and needs no second canvas; `ctx.filter = blur()` was rejected because it has not shipped in every browser and the two windows must agree pixel for pixel (they run in one browser, so any deterministic method agrees with itself). The bitmap raster ignores feather: its hard edge sits where the feathered edge crosses 50 %, which is what "is this cell fogged?" wants. The feather width is 30 % of a cell (4–64 px), chosen by the DM view, not stored as a setting; snapped shapes are never feathered (cells have hard edges).
- **Undo is a shared op; redo is the DM re-sending.** `map/fog-undo { id }` drops the last op of a map's log. The player applies it like any other op and its mask updater already rebuilds when the log shrinks, so both windows converge without any new message type or any pixel traffic. What undo dropped goes on a DM-only per-map redo stack (`state/fogHistory.ts`); redo dispatches it again as a `map/fog-op`. Any new fog op discards the map's redo stack; redo's own dispatch does not. The undo history *is* the log: depth is `fogOps.length`, at least `FOG_KEEP_OPS` (32) after a compaction — which is why ADR 0012 keeps 32 — and ops baked into the base are gone. Undo across the compaction boundary is impossible by design.
- **Gestures commit on release; the preview does the live work.** A brush stroke is one op dispatched on mouse-up (ADR 0012's advice: keeps the log short, makes one stroke one undo step, keeps compaction rare). The DM still sees fog vanish under the brush as they drag: the in-progress shape is a Konva node drawn *inside the fog layer* with `destination-out` (`MapStage`'s `fogOverlay`), so each frame costs one overlay redraw whatever the map size and the mask canvas is untouched until the op lands. A hide preview is a red tint. Snapping is applied to the preview too, so what is shown is what is committed. Consequence: the TV updates at the end of a stroke, not during it; the 100 ms latency budget is measured from that release.
- **Snap means "the cells the shape touches".** `snapShapeToCells` tests each candidate cell (shrunk by 0.001 px so an edge on a grid line does not spill) for positive-area overlap with the shape — exact geometry (rect / circle / capsule / polygon vs. rectangle), not sampling — merges runs per row and clips to the map. A rectangle dragged from inside one cell to inside another therefore covers exactly the cells between, inclusive.
- **Tool settings are DM UI state**, held by `DmView` (`FogToolSettings`), not part of the campaign nor the presentation: they are how the DM is working, not what the players see.

## Alternatives considered
- **Streaming brush segments as ops during the drag** (live TV updates mid-stroke). Rejected: dozens of ops per stroke would hit compaction constantly (main-thread bakes mid-drag), bloat the autosaved document, and break "one stroke = one undo step" unless ops were grouped and compaction made group-aware.
- **Applying the in-progress stroke to the DM's mask canvas directly.** Rejected: feathered painting is not idempotent (painting the stroke again at commit compounds the alpha), and an abandoned stroke would need a full rebuild; the overlay punch-through gives the same picture for free.
- **Undo as a DM-only truncation with the player receiving a fresh snapshot.** Rejected: a snapshot is far larger than one op and would bypass the sequenced delta path for no gain.
- **`ctx.filter` for feather, with radial gradients for circles.** Rejected as above; gradients do not extend to polygons and strokes.
- **Cells as one op per cell, or as one polygon.** Rejected: one op per cell breaks undo granularity; a union of cells is not one simple polygon.

## Consequences
- Documents written by this build are refused by T007 builds (`newer-schema`); v4 documents load unchanged.
- `FogRaster` gained `fillRects` and `fillStroke` and a `feather` argument on every shape call; the canvas raster's fake context in tests records `shadowBlur` / `translate` / `stroke` / `rect` too.
- The undo depth before a compaction is the whole log (up to 63); after one it is 32. Undo during an in-flight bake still works: the bake verifies its prefix, and undo only ever removes from the tail.
- Measured in headless Chromium on a 4096 × 2048 blank map: a ~150-event brush drag runs at a 16.7 ms median frame (60 Hz) and committing the stroke to the mask takes about 2 ms (`e2e/fog.spec.ts`, `[perf]` line).
