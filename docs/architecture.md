# Architecture

Local-first TypeScript SPA. No backend. Ships as static files; runs offline once loaded.

## Windows & sync
- Routes: / campaign manager, /dm DM view, /player player view. Hash router (`createHashRouter`) so static hosting and file:// URLs work. Route table lives in `app/src/routes.tsx`; path constants in `app/src/routePaths.ts` (dependency-free so any module can import them). `/dm` mounts `dm/DmRoute.tsx`, which opens a campaign from storage (load-on-start) before rendering `DmView` and runs autosave while mounted; `/` mounts `CampaignManager.tsx` (list, create, open, rename, delete).
- DM view opens /player with window.open (named window `tablemap-player`, `popup` feature for a chrome-less window). The DM window retains the handle in a controller (`app/src/dm/playerWindow.ts`, pure logic with injectable deps; React binding `usePlayerWindow.ts`) and uses it to focus, full-screen and close the player window. Re-clicking "Open" focuses the existing window instead of spawning another. The hook polls the handle (500 ms) for closed/fullscreen changes because no cross-window event survives the popup's own navigation.
- Fullscreen: the DM toggle calls `requestFullscreen` on the player document via the handle. Browsers only honour that from a user gesture in the *target* window, so the request is often denied (it is in headless Chromium). The DM view then shows a hint, and the player view offers an in-window fallback: press **F** or double-click. See ADR 0005. The OS puts the window on the TV (Window Management API where available, manual drag as fallback).
- Player/DM boundary: `src/player/**` must never import from `src/dm/`. Enforced by an ESLint `no-restricted-imports` rule scoped to `src/player` and by a unit test (`src/player/boundary.test.ts`).
- DM layout (`DmView`): top toolbar (player-window controls), left sidebar (campaign name, `dm/MapPanel.tsx`, tools: `dm/GridPanel.tsx`, `dm/FogPanel.tsx`, `dm/CalibrationPanel.tsx`), main canvas area (`dm/DmCanvas.tsx`, the Konva stage for the active map with wheel zoom / drag pan and a **Fit** button). Canvas tools are mutually exclusive: `DmView` holds one `DmTool` (`none` | `align` | `fog-reveal`), reset whenever the active map changes. The whole DM view is a drop target for image files (`data-dragging` + an overlay while a file is over it); the file picker lives in the map panel. Import UI state (queue, "Importing…", last error) is `dm/useMapImport.ts`.
- Grid tools (T005): `GridPanel` edits the active map's cell size, offset and the per-view style (show / colour / opacity for the DM view and the player view separately) through `MapActions.setGrid`, and toggles the **alignment tool**. `DmView` owns the "aligning" flag (reset whenever the active map changes) and passes `DmCanvas` an `alignment` prop (`onAligned(geometry)`, `onCancel`). While aligning, the canvas hands the stage a `pointerTool` instead of drag-pan, feeds the pure state machine in `map/alignment.ts` with pointer events in map pixels, draws the preview box as a stage `overlay`, shows a hint (`data-testid="align-hint"`, plus `align-error` when the box is too small), and listens for Esc. A completed alignment becomes one `map/set-grid` op with the derived `cellSize`/`offsetX`/`offsetY` and the styles untouched.
- Fog of war (T007, ADR 0012): `FogPanel` offers **Reveal rectangle…** (toggles the `fog-reveal` tool), **Hide all** / **Reveal all**, and the log length (`data-testid="fog-op-count"`). With the tool on, `DmCanvas` takes a `fog` prop (`{ mode, onShape, onCancel }`): a drag becomes one `rect` shape in map pixels (drags under `FOG_RECT_MIN_PX` = 2 screen px are clicks and ignored), previewed as a dashed box in the overlay layer; the tool stays on for the next rectangle, Esc abandons a drag in progress or leaves the tool; `data-fogging` on the canvas surface reports the mode. Shapes go to `FogActions.reveal`, which dispatches `map/fog-op`. The DM canvas reads the map's fog base PNG from the database (`useAssetBlob`) and hands it to the stage as `fogBase`.
- Calibration (T006, ADR 0011): `CalibrationPanel` shows the display the player window reported, the cell unit (1 inch / 25 mm), the **overview** override, and the two ways to calibrate: **ruler** (puts the player on a ruler screen showing a white square; ±1/±10 buttons and a size field grow/shrink it; "It measures 1 inch: save") and **TV size** (diagonal + native resolution, prefilled from the display report). Saving goes through a `CalibrationSession` (`state/calibrationSession.ts`, created by `DmView`, injectable in tests) that persists per display and updates the store's `presentation`, which the sync layer pushes to the player.
- **Single source of truth is the DM window Zustand store.** The player window is a dumb mirror: it applies sync messages received over a BroadcastChannel and renders. It never mutates state. Message schema lives in app/src/state/sync.ts (typed, versioned). Full-state snapshot on player connect; deltas after (fog ops are sent as operations, never bitmaps). Binary assets (map images) are pushed by the DM as `asset` messages on the same channel (ADR 0008); the player never reads storage. How the player should present scenes on its display (calibration, overview, ruler screen) travels as an unsequenced `presentation` message (ADR 0011); the player's `hello` carries its `DisplayInfo` so the DM can look up that display's calibration.

### State & sync modules (`app/src/state/`)
- `model.ts` — scene-level data model: `MapScene` (id, name, `imageAssetId | null`, `backgroundColor`, size, `grid`, fog: `fogMaskAssetId` (the base PNG, null = fully fogged) + `fogOps` (the op log) + `fogOpsFrom` (history index of `fogOps[0]`; ADR 0012), tokens, annotations), `GridSettings` = `GridGeometry` (`cellSize`, `offsetX`, `offsetY` in map pixels; any offset is legal, renderers wrap it into the first cell) + one `GridStyle` (`visible`, `color`, `opacity` 0..1) per `GridView` (`dm`, `player`; ADR 0010), `Token`, `Annotation`, `AssetId`, `AssetKind`, `SCHEMA_VERSION` (4), plus structural type guards. Binary data is referenced by `AssetId`, never embedded.
- `fog.ts` — fog operations (ADR 0012), pure and shared by both windows: `FogMode` (`reveal` | `hide`), `FogShape` (`rect` | `circle` | `polygon` with flat points, all in map pixels), `FogOp` (`{ type: "fill", mode }` | `{ type: "shape", mode, shape }`), constructors `fogFill`, `fogShape`, `rectShape(a, b)` (any two corners → normalised rect), `cloneFogOp`, and guards `isFogOp`/`isFogShape`.
- `shared.ts` — `SharedState` (the only state the player ever sees: `campaignName`, `maps`, `activeMapId`) plus `SharedOp`, the discriminated union of operations that change it (`campaign/set-name`, `campaign/replace`, `map/add` (with optional insert index), `map/remove` (clears `activeMapId` if it pointed there), `map/rename`, `map/set-active` (ignored for unknown ids), `map/set-grid` (replaces a map's whole `GridSettings`; no-op for unknown ids or unchanged settings; `gridSettingsEqual`), `map/fog-op` (appends a copy of one `FogOp` to a map's log; earlier entries keep their identity), `map/fog-compact` (`{ id, baseAssetId, opCount }`: the first `opCount` ops are baked into `baseAssetId`, which becomes the base; they are dropped and `fogOpsFrom` advances; ignored when the log is shorter than `opCount`)), and the pure reducer `applyOp`. Both windows run the same reducer. `SharedState` is also the body of the persisted campaign document, so it must stay plain JSON. Later tasks extend the state and add op kinds here.
- `maps.ts` — pure scene helpers: `createImageMapScene`, `createBlankMapScene` (size in cells × cell size, colour; both fully fogged: null base, empty log), `duplicateMapScene` (deep copy, shares the immutable image asset, takes the id of a *copied* fog base, copies the fog log), `findMap`/`activeMap`, `sceneAssetIds`/`referencedAssetIds`, and `assetIdsForPlayer` (active map's assets first, then every other map's).
- `mapActions.ts` — the DM's map operations over a store + database: the import pipeline `importMapImage(db, campaignId, file, { measureImage })` (validate PNG/JPEG/WebP by MIME or extension → decode for size (`measureImageInBrowser`: `createImageBitmap`, `Image` fallback; injected in tests) → `putAsset` → `createImageMapScene`; throws `MapImportError`, writes nothing on failure) and `createMapActions(store, db)` → `importImage` (add + activate in one dispatch), `createBlank`, `duplicate` (copies the fog-mask Blob, inserts after the original, activates the copy), `rename`, `remove` (then deletes assets nothing references any more — image assets are shared by duplicates), `setActive`, `setGrid` (one `map/set-grid` op).
- `fogActions.ts` — the DM's fog operations over a store + database (ADR 0012): `createFogActions(store, db, { bake, compactAt?, keepOps?, newId?, onError? })` → `apply(mapId, op)` (one `map/fog-op`; nothing for unknown maps), `reveal`/`hide(mapId, shape)`, `revealAll`/`hideAll(mapId)`, `idle()` (tests: wait for compactions). **Compaction**: once a log has `FOG_COMPACT_AT` (64) ops, the first `length − FOG_KEEP_OPS` (32) are baked with the injected `bake` (browser: `map/fogMask.ts: bakeFogMask`) into a PNG, stored as a `fog-mask` asset, and dropped with one `map/fog-compact`; the baked prefix is re-verified against the live log after every await (aborts, storing nothing, if it changed), the previous base is deleted once unreferenced, one compaction runs per map at a time, and a failed one is reported via `onError` and retried on the next op. Off-limits to `src/player/**`.
- `assetCodec.ts` — `blobToBase64` / `base64ToBlob` for `asset` messages.
- `calibration.ts` — physical calibration, all pure (ADR 0011): `DisplayInfo` (`width`, `height` in CSS px, `pixelRatio`, `left`, `top`) + `readDisplayInfo(window)` + `displayKey` (the settings key, `WxH@dpr+left,top`); `CellUnit` (`inch` | `mm25`) and `cellInches`; `DisplayCalibration` (`pxPerInch` in CSS px, `method` `square` | `diagonal`, `updatedAt`); derivations `pxPerInchFromSquare(sizePx, unit)` and `pxPerInchFromDiagonal({ diagonalInches, widthPx, heightPx, pixelRatio })` (null outside 10–600 px/in); `lockedScale(pxPerInch, unit, cellSizePx)` = the player stage scale; `PlayerPresentation` (`{ pxPerInch | null, cellUnit, overview, target }`, what the `presentation` message carries) with `presentationMode` → `calibrating` | `calibrated` | `overview` | `uncalibrated`; `PresentationState` (the DM-only store slice: `playerDisplay`, `calibration`, `cellUnit`, `overview`, `target`) and `playerPresentation(state)`.
- `calibrationSession.ts` — DM-side plumbing over a store + database: `createCalibrationSession(store, db)` → `start()` (loads the cell unit; loads a display's calibration whenever `presentation.playerDisplay` changes, dropping stale loads), `save(calibration)` / `clear()` (persist for the connected display, then apply; false when no display is known), `setCellUnit`. Off-limits to `src/player/**`.
- `store.ts` — the DM store (`createTableStore`, app-wide `tableStore`, `useTableStore` hook). Shared state changes only via `dispatch(...ops)`, which applies the reducer, bumps `seq` by one per dispatch and notifies `onOps` listeners. `campaignId` (DM-only) names the persisted document the shared state belongs to; `openCampaign(campaign)` sets it and applies `campaign/replace` in one commit, `closeCampaign()` clears it. `presentation` (DM-only, `PresentationState`) changes via `setPresentation(patch)` and `setPlayerDisplay(display)` (a different display drops the loaded calibration); neither bumps `seq`. **`src/player/**` may not import this module** (ESLint `no-restricted-imports` + `boundary.test.ts`).
- `sync.ts` — the protocol (ADR 0006, ADR 0008, ADR 0011): `PROTOCOL_VERSION`, `SYNC_CHANNEL_NAME`, message types `hello` (optionally with the player's `display`) / `snapshot` / `delta` / `asset` (`{ id, kind, mime, data: base64 }`, unsequenced) / `presentation` (`PlayerPresentation`, unsequenced, latest wins), constructors, `encodeMessage` (JSON string) and `decodeMessage`/`validateMessage` (never throw; reject other versions, unknown types and bad shapes).
- `transport.ts` — `SyncTransport` interface (`post`, `onMessage`, `close`). `createBroadcastTransport` wraps a BroadcastChannel; `createMemoryHub` is the in-test replacement with the same fan-out (never echoes to the sender); `createNullTransport` is used where BroadcastChannel is missing.
- `mirror.ts` — the player-side `MirrorState` (`connecting | synced`, `seq`, `shared | null`, `assets: Record<AssetId, Blob>`, `presentation: PlayerPresentation`) and the pure `reduceMirror(mirror, message)`: snapshots always replace; a delta applies only if `seq === mirror.seq + 1`; stale/duplicate deltas are ignored; a gap, or a delta before any snapshot, sets `resync` so the caller re-requests a snapshot — as does a **DM** `hello`, so a restarted DM learns this player's display. `asset` messages are decoded into `assets` whenever they arrive (undecodable data is ignored); after every snapshot/delta, assets the state no longer references are dropped. `presentation` messages replace `presentation` (same object if identical); snapshots/deltas carry it through.
- `dmSync.ts` — `startDmSync(store, transport, { assets? })`: on start sends `hello(dm)` + a snapshot (so already-open players catch up) + the presentation, answers every player `hello` with a snapshot + presentation, forwards each dispatch as one `delta`, and sends a `presentation` whenever the store's `playerPresentation` changes. A player hello carrying a `display` is recorded with `setPlayerDisplay` (DM-only bookkeeping; the only thing a received message may write). Nothing received can mutate the *shared* state. With an `AssetSource` it also pushes every referenced asset not yet sent this session (queued, one at a time, `assetIdsForPlayer` order) after the snapshot/delta, and re-sends all of them on a `hello` from a client id it has not served yet (a known player re-announcing gets only the snapshot + presentation).
- `playerSync.ts` — `startPlayerSync(mirror, transport, { display? })` → `{ stop, announce }`: sends `hello(player, id, display?.())` on start, whenever `reduceMirror` asks for a resync, and on `announce()`; writes decoded messages into the mirror. **The player only ever sends `hello`.**
- React bindings: `dm/useDmSync.ts` (DM view; passes an `AssetSource` backed by `getAsset`) and `player/usePlayerSync.ts` (player view) create the transport inside an effect so StrictMode's double mount gets a fresh channel; both views accept an injected `createTransport` for tests. `usePlayerSync` also takes a `readDisplay` (default: `window.screen`, undefined where it is unknown, e.g. jsdom) and re-announces when the display key changes — checked on `resize` and every `DISPLAY_POLL_MS` (1 s), because the popup opens on the laptop and is dragged to the TV afterwards. `PlayerView` exposes `data-sync-status` / `data-sync-seq` / `data-active-map-id` / `data-view-mode` on its root for e2e assertions.
- Reconnect: a reloaded player window is simply a new endpoint; its `hello` fetches a full snapshot and deltas resume from that `seq`. A player opened before the DM stays `connecting` until the DM's start-up snapshot arrives; it then re-announces so the DM learns its display and sends the matching calibration.

### Persistence modules (`app/src/state/`, ADR 0007)
- `campaign.ts` — the persisted document `Campaign = { schemaVersion, id, name, createdAt, updatedAt, state: SharedState }`, `CampaignSummary` (what the manager lists), `newCampaign`, `isCampaign`, and `migrateCampaign` (never throws; brings older documents to `SCHEMA_VERSION`, reports `newer-schema` / `invalid`).
- `db.ts` — the Dexie database `TableMapDb` (`getDb()` is the app-wide instance; tests construct their own with a unique name). Tables: `campaigns` (documents, JSON only; indexed by `name`, `updatedAt`), `assets` (`{ id, campaignId, kind, blob }` — map images, token images, fog masks as Blobs), `settings` (key/value: last opened campaign; later, per-display calibration).
- `persistence.ts` — async functions over a `TableMapDb`: `listCampaigns`, `createCampaign`, `loadCampaign` (migrates; throws `CampaignLoadError` for corrupt/newer documents), `saveCampaign`, `saveCampaignState` (what autosave calls; false if the campaign was deleted meanwhile), `renameCampaign`, `deleteCampaign` (also deletes its assets and the last-opened pointer), `putAsset`/`getAsset`/`deleteAsset`/`listAssetIds`, `getLastCampaignId`/`setLastCampaignId`, `getDisplayCalibration`/`setDisplayCalibration` (settings row `calibration:<displayKey>`; null clears; unreadable rows read as null), `getCellUnit`/`setCellUnit` (settings row `cellUnit`, default `inch`), and `resolveStartupCampaign` (last opened → most recently updated → new "Untitled campaign"; unreadable documents are skipped).
- `autosave.ts` — `startAutosave(store, save, { debounceMs })`: subscribes to the DM store; any change to `shared` while `campaignId` is set schedules a write of the latest state after the debounce (default 400 ms); bursts coalesce; writes are serialised; opening another campaign or closing flushes first; `flush()`/`stop()` for unmount and `pagehide`. Pure logic, no IndexedDB.
- `session.ts` — `openStoredCampaign(store, db, id)` and `bootstrapCampaign(store, db)` (load-on-start; no-op when a campaign is already open; concurrent calls share one promise so StrictMode's double effect cannot create two default campaigns).
- `src/player/**` may not import `db`, `persistence`, `autosave`, `session`, `calibrationSession` or `fogActions` either (same ESLint rule + boundary test): the player never touches storage.

## Rendering (`app/src/map/`, shared by both views; imports neither `dm/` nor the DM store)
- Konva stage with layers bottom-to-top: map image -> grid -> tokens -> annotations -> fog -> tool overlay.
- `MapStage.tsx` — the react-konva stage. Props: `scene`, decoded `image` (or null), container `size`, `viewport` (`{ x, y, scale }` = stage transform), `gridView` (`dm` | `player`: which of the scene's two grid styles to draw and how opaque the fog is — the DM canvas passes `dm`, the player view `player`), `interactive` (wheel zooms around the pointer, dragging the stage pans; the new viewport is reported via `onViewportChange` — the caller owns it), `pointerTool` (`{ onDown, onMove, onUp }` receiving map-pixel points from the stage's mouse/touch events; while set, drag-pan is off but wheel zoom stays), `overlay` (Konva nodes drawn in a top layer, in map coordinates), `fogBase` (the Blob of the scene's fog base PNG, undefined until available). Layer 1: a `Rect` in `scene.backgroundColor` (all of a blank map) under the `Image`; layer 2 (only if the chosen style is visible): the grid as one `Shape` (`strokeScaleEnabled=false` so lines stay 1 px at any zoom); layer 3 (always): the fog mask canvas as a Konva `Image` at `FOG_ALPHA[gridView]` (0.5 dm, 1 player); layer 4 (only with an overlay). The wrapper exposes `data-map-id`, `data-map-name`, `data-image-status` (`none | waiting | loading | loaded | error`), `data-scale`, `data-grid-view`, `data-grid-visible`, `data-tool`, `data-fog-status` (`ready | bridged | waiting`, see below), `data-fog-ops` (log length) and `data-fog-history` (`fogOpsFrom + log length`, the map's total fog op count — what e2e watches to time a reveal) for tests.
- `viewport.ts` — pure math: `fitToView` (contain + centre with padding), `centerAtScale` (dictated scale, map centred; used by the calibrated player view), `zoomAt` (keeps the map point under the pointer fixed; scale clamped to 0.05–8), `wheelZoomFactor`, `panBy`, `screenToMap`/`mapToScreen`. `grid.ts` — `normalizeOffset`, `gridLinePositions`/`gridLines` from `GridGeometry` (offset wrapped into the first cell), and `alignGridToSquare(a, b)`: two opposite corners of one printed square (any order, either diagonal) → `{ cellSize, offsetX, offsetY }`; cell size is the mean of the box's width and height, offset is the box's top-left wrapped into the first cell; null below `MIN_ALIGN_CELL_SIZE` (4 px). `alignment.ts` — the alignment tool's pure state machine (`reduceAlignment(state, event)`: `idle` → `dragging` on press; release after ≥ `minDrag` completes, a shorter release is a click and moves to `second`, where the next press completes; `cancel` from anywhere; `alignmentBox` gives the preview rectangle). `minDrag` is `ALIGN_CLICK_THRESHOLD_PX` (6 screen px) divided by the viewport scale.
- `useImageElement.ts` — Blob → object URL → decoded `HTMLImageElement` (revoked on change/unmount). `useContainerSize.ts` — ResizeObserver-backed element size.
- DM (`dm/DmCanvas.tsx`): reads the active map's image Blob and fog base Blob from the database (`dm/useAssetBlob.ts`, which also provides object URLs for the panel thumbnails), fits the viewport whenever the active scene changes, then leaves pan/zoom to the user. Player (`PlayerView`): takes both Blobs from the mirror's `assets`, shows the idle campaign title when no map is active, and picks its viewport from the mirror's `presentation` (see Calibration below).
- Fog (T007, ADR 0012): the mask is an offscreen canvas the size of the map, derived from the scene's base PNG + op log, never received as pixels while editing. `fogRaster.ts` — `FogRaster<Base>` (`reset(base | null)`, `fillAll`, `fillRect`, `fillCircle`, `fillPolygon`, each with a `FogMode`) and `applyFogOp(s)`, the single place that turns a `FogOp` into raster calls; two implementations: `createCanvasFogRaster` (production: `hide` = `source-over` black, `reveal` = `destination-out`; polygons even-odd) and `createBitmapFogRaster` (a `Uint8Array` alpha, 255 hidden / 0 revealed, pixel-centre coverage; `isHidden(x, y)`, `hiddenFraction()` — the unit-test double and, later, the "token under fog" query). `fogMask.ts` — `createFogMaskUpdater(raster)`: `update(scene, base)` returns `ready` (incremental: only ops past the history index it has applied are drawn; or a rebuild from the base when the map, the base or the log's past changed), `bridged` (the base changed by compaction but its PNG has not arrived/decoded: the pixels are already right, so keep them, apply new ops, rebuild once it lands) or `waiting` (a base this window never had: fully fogged, the safe default); `bakeFogMask(scene, baseBlob, opCount)` renders base + prefix to a PNG Blob for compaction. `useFogMask.ts` — one canvas per stage, updated in a layout effect, with an `onDraw` callback that `batchDraw`s the Konva layer. DM composites the mask at 50 % alpha, player at 100 %. Feathering (radial-gradient brush) arrives with T008.
- Calibration (T006, ADR 0011): the player view's mode is `presentationMode(presentation)`. **calibrated** — stage scale locked to `lockedScale(pxPerInch, cellUnit, scene.grid.cellSize)` so one cell is `pxPerInch * cellInches` CSS px whatever the image resolution, map centred (`centerAtScale`; panning is a later task). **overview** — the DM's override: fit to window plus a "not to scale" badge (`data-testid="player-overview-badge"`). **uncalibrated** — fit to window. **calibrating** — the ruler screen: a plain `div` square of exactly `target` CSS px (`data-testid="calibration-target"`, `data-size-px`) with the unit label, instead of the map. Konva and the DOM both draw in CSS px, so the square and a calibrated cell agree at any device pixel ratio. The DM stage keeps free pan/zoom.

## Storage
- Dexie (IndexedDB), database `tablemap`: `campaigns` (one JSON document per campaign = metadata + `SharedState`), `assets` (map images, fog-mask PNGs, token images as Blobs, keyed by `AssetId` and owned by a `campaignId`), `settings` (last opened campaign; per-display calibration under `calibration:<displayKey>`; the `cellUnit` preference — ADR 0011). Blobs are never serialised into the document; documents reference them by id. See ADR 0007. Calibration is deliberately *not* in the campaign document: it belongs to the TV, applies to every campaign, and must not travel in exports.
- Autosave is a debounced subscription on the DM store (`state/autosave.ts`), started by the `/dm` route and flushed on unmount / `pagehide`. Load-on-start opens the last campaign (or creates "Untitled campaign").
- Every document carries `schemaVersion` (currently 4: v1 → v2 adds `MapScene.backgroundColor`, ADR 0009; v2 → v3 turns the single grid style into `grid.dm` + `grid.player`, ADR 0010; v3 → v4 adds the fog log `fogOps` + `fogOpsFrom`, ADR 0012); `migrateCampaign` runs the `MIGRATION_STEPS` chain forward on load and refuses newer documents. Dexie `version(n)` is only bumped for index changes.
- Map images are written once at import (`putAsset`, kind `map-image`) and referenced by `MapScene.imageAssetId`; duplicating a map shares the image, so an asset is deleted only when the last map referencing it is removed (`mapActions.remove`).
- Fog masks (kind `fog-mask`, PNG) are written by compaction of a map's fog log (`fogActions`, ADR 0012) and referenced by `MapScene.fogMaskAssetId`; the previous base is deleted once nothing references it. A map's fog therefore persists as the base PNG plus the ops since it in the document; a map that has never been compacted has only the ops. Duplicating a map copies the base Blob under a new id.
- Export/import: JSZip bundle — campaign.json (the same document) + assets/ blobs. Importers run the same migration.

## Testing strategy
- Unit (Vitest): state slices, sync protocol encode/decode, fog op math, grid/calibration math, persistence round-trips (fake-indexeddb). Sync is tested end-to-end without a browser by wiring `startDmSync` and `startPlayerSync` through `createMemoryHub` (`src/state/syncDrivers.test.ts`).
- Calibration: `state/calibration.test.ts` covers both px-per-inch derivations, the locked-scale invariant (`cellSize * scale == pxPerInch * cellInches` for any cell size) and display keys; `state/calibrationSession.test.ts` (node, fake-indexeddb) covers load-on-display-report, reload, display switching and stale loads; `state/syncDrivers.test.ts` covers the display report in `hello`, presentation pushes, re-announce on DM start and on display change; `player/usePlayerSync.test.tsx` asserts the player stage's `data-scale` under calibration for two maps with different cell sizes, the overview badge, the ruler screen and re-announcing on `resize`/poll; `dm/CalibrationPanel.test.tsx` drives the ruler and TV-size flows through `DmView` with an injected in-memory `CalibrationSession`. `e2e/calibration.spec.ts` runs the whole thing in Chromium (the only place `window.screen` is real): display reported, ruler square measured with `getBoundingClientRect`, `data-scale` on the player stage for 50 px and 100 px cells, overview badge, player reload and DM reload (after polling IndexedDB for autosave).
- Grid fixture: `src/test/gridFixture.ts` describes a map with a known printed grid (400×300, 50 px cells, offset (12, 7)) and gives the corners of any cell; `map/grid.test.ts` and `map/alignment.test.ts` check the alignment maths against it (exact, and ±1 px under click jitter) and `dm/GridPanel.test.tsx` drives the real canvas with mouse events (Konva fires plain `mousedown`/`mousemove`/`mouseup` on the stage under jsdom; with a zero-size container the viewport is the identity, so screen = map pixels). The same grid is drawn in `e2e/fixtures/grid-map.png`, regenerated by `npm run fixture:grid` (`scripts/make-grid-fixture.mjs`, a dependency-free PNG writer), for future e2e coverage.
- Fog (T007): `state/fog.test.ts` (guards, constructors), `state/shared.test.ts` (`map/fog-op` / `map/fog-compact` semantics, op identity across appends), `state/campaign.test.ts` (v3 → v4), `map/fogRaster.test.ts` (op maths on the bitmap raster: fill, rect incl. fractional edges and clipping, circle, concave/self-intersecting polygons; DM-incremental vs player-replay byte identity; the canvas raster's composite-operation sequence against a recording context), `map/fogMask.test.ts` (updater: incremental vs rebuild, resize, waiting, compaction bridging, base change), `state/fogActions.test.ts` (node, fake-indexeddb: dispatches, compaction into a `fog-mask` PNG, chained compactions, aborted compaction on a rewritten log, ops during a bake, failed bakes), `state/syncDrivers.test.ts` (fog ops cross the hub as deltas only and replay to the same mask; compaction and snapshots carry the base), `dm/FogPanel.test.tsx` (hide/reveal all, the rectangle tool via mouse events, Esc, tool exclusivity, map switch) and `map/MapStage.test.tsx` (fog layer always present, `waiting` without a base). `e2e/fog.spec.ts` runs it in Chromium: blackout by default (player centre pixel black, DM centre dimmed to half the fixture colour), a dragged rectangle shows map pixels on the player and leaves the rest black, hide all / reveal all, DM-click-to-player-repaint latency under 100 ms (1 s with `CI` set; `Date.now()` stamped by a capture-phase click/mouseup listener on the DM page and a `MutationObserver` on the player stage's `data-fog-history`), fog kept per map across a scene switch, a DM reload (after polling the document for the autosaved log) and a player reload, and 64 alternating fills compacting into one `image/png` `fog-mask` asset that both windows then render from (also after a DM reload). Pixels are read by compositing every layer canvas of a stage in the page (`compositePixel`), so the check sees what a screenshot would; the blank map is sampled just off centre because its centre lies on a grid line.
- E2E (Playwright): multi-page tests — one context, DM page + player page — asserting the player render reacts to DM actions (fog reveal, blackout, ping, scene switch). Visual sanity via screenshot assertions on the fog layer. The player page is obtained by clicking "Open player view" and awaiting `context.waitForEvent("page")` (see `e2e/player-window.spec.ts`). `e2e/sync.spec.ts` covers live updates, snapshot-on-open, player reload and a player opened before the DM.
- Unit tests that need source text (e.g. the player/DM boundary test) use Vite's `import.meta.glob(..., { query: "?raw" })` rather than Node `fs`, so no Node typings are needed.
- `src/test/setup.ts` (Vitest `setupFiles`) installs `fake-indexeddb/auto`, so components that touch storage work under jsdom. Tests that store Blobs (`persistence.test.ts`, `session.test.ts`, `mapActions.test.ts`) run under `// @vitest-environment node`: jsdom's `Blob` is not structured-cloneable by fake-indexeddb, Node's is. Every persistence test uses a uniquely named `TableMapDb` and deletes it afterwards. jsdom's Blob also lacks `arrayBuffer()`/`text()`; `src/test/blob.ts` reads Blobs via `FileReader` in jsdom tests.
- Konva under jsdom: `vite.config.ts` aliases the bare `konva` import to `konva/lib/index.js` (its Node entry requires the native `canvas` package) and inlines `react-konva` so the alias applies to it; `setup.ts` stubs `HTMLCanvasElement.prototype.getContext("2d")` with a no-op context. Component tests can therefore mount `MapStage` and assert on the scene graph, data attributes and wheel handling; what is actually painted is asserted in e2e by reading pixels from the stage canvas.
- `e2e/persistence.spec.ts` covers the reload-restores-campaign criterion and the campaign manager against real Chromium IndexedDB (reading the database directly via `page.evaluate` to wait for autosave).
- `e2e/maps.spec.ts` covers import (file picker and drag-drop via a `DataTransfer` built in the page), the Blob in IndexedDB, re-render after reload, the player showing the active map (pixel colour of the stage canvas, polled because Konva draws on the next animation frame), scene switching, player reload, blank maps, rename/duplicate/delete and wheel/drag on the DM canvas.
