# Architecture

Local-first TypeScript SPA. No backend. Ships as static files; runs offline once loaded.

## Windows & sync
- Routes: / campaign manager, /dm DM view, /player player view. Hash router (`createHashRouter`) so static hosting and file:// URLs work. Route table lives in `app/src/routes.tsx`; path constants in `app/src/routePaths.ts` (dependency-free so any module can import them). `/dm` mounts `dm/DmRoute.tsx`, which opens a campaign from storage (load-on-start) before rendering `DmView` and runs autosave while mounted; `/` mounts `CampaignManager.tsx` (list, create, open, rename, delete).
- DM view opens /player with window.open (named window `tablemap-player`, `popup` feature for a chrome-less window). The DM window retains the handle in a controller (`app/src/dm/playerWindow.ts`, pure logic with injectable deps; React binding `usePlayerWindow.ts`) and uses it to focus, full-screen and close the player window. Re-clicking "Open" focuses the existing window instead of spawning another. The hook polls the handle (500 ms) for closed/fullscreen changes because no cross-window event survives the popup's own navigation.
- Fullscreen: the DM toggle calls `requestFullscreen` on the player document via the handle. Browsers only honour that from a user gesture in the *target* window, so the request is often denied (it is in headless Chromium). The DM view then shows a hint, and the player view offers an in-window fallback: press **F** or double-click. See ADR 0005. The OS puts the window on the TV (Window Management API where available, manual drag as fallback).
- Player/DM boundary: `src/player/**` must never import from `src/dm/`. Enforced by an ESLint `no-restricted-imports` rule scoped to `src/player` and by a unit test (`src/player/boundary.test.ts`).
- DM layout (`DmView`): top toolbar (player-window controls, then the **Blackout** and **Show splash** switches — `blackout-toggle` / `splash-toggle`, `aria-pressed`), left sidebar (campaign name, `dm/MapPanel.tsx`, tools: `dm/GridPanel.tsx`, `dm/FogPanel.tsx`, `dm/CalibrationPanel.tsx`, `dm/PlayerViewPanel.tsx`), main canvas area (`dm/DmCanvas.tsx`, the Konva stage for the active map with wheel zoom / drag pan, a **Fit** button and the player viewport rectangle). Canvas tools are mutually exclusive: `DmView` holds one `DmTool` (`none` | `align` | `fog`), reset whenever the active map changes. The whole DM view is a drop target for image files (`data-dragging` + an overlay while a file is over it); the file picker lives in the map panel. Import UI state (queue, "Importing…", last error) is `dm/useMapImport.ts`.
- Grid tools (T005): `GridPanel` edits the active map's cell size, offset and the per-view style (show / colour / opacity for the DM view and the player view separately) through `MapActions.setGrid`, and toggles the **alignment tool**. `DmView` owns the "aligning" flag (reset whenever the active map changes) and passes `DmCanvas` an `alignment` prop (`onAligned(geometry)`, `onCancel`). While aligning, the canvas hands the stage a `pointerTool` instead of drag-pan, feeds the pure state machine in `map/alignment.ts` with pointer events in map pixels, draws the preview box as a stage `overlay`, shows a hint (`data-testid="align-hint"`, plus `align-error` when the box is too small), and listens for Esc. A completed alignment becomes one `map/set-grid` op with the derived `cellSize`/`offsetX`/`offsetY` and the styles untouched.
- Fog of war (T007 + T008, ADR 0012, ADR 0013): `FogPanel` edits the DM-only `FogToolSettings` (`dm/fogTool.ts`: `mode` reveal | hide, `tool` brush | rect | lasso, brush `radius` in map px (slider 4–400, default 40), `feather` on by default, `snap` off by default) that `DmView` holds in state, turns the `fog` tool on with **Brush** / **Rectangle** / **Lasso** (clicking the active one, **Stop** or Esc turns it off), offers **Undo** / **Redo** (also Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z, Ctrl/Cmd+Y from anywhere but a text field), **Hide all** / **Reveal all**, and the log length (`data-testid="fog-op-count"`; buttons are `fog-mode-*`, `fog-tool-*`, `fog-brush-radius`, `fog-feather`, `fog-snap`, `fog-undo`, `fog-redo`). With the tool on, `DmCanvas` takes a `fog` prop (`{ settings, onShape, onCancel }`) and feeds the stage's pointer events to the pure gesture machine `map/fogGesture.ts` (`reduceFogGesture`: brush → one `stroke` of the thinned drag path, `FOG_MIN_STEP_PX` = 3 screen px between kept points, a click is a one-point stroke = a dot; rect → the box, under `FOG_MIN_DRAG_PX` = 2 screen px is a click and ignored; lasso → the drag path closed into a `polygon`, needs ≥ 3 kept points and a box over the minimum). With `snap` on the shape is expanded to whole grid cells by `map/fogSnap.ts` (`snapShapeToCells` → one `rects` shape; feather is then off: cells have hard edges). The live preview is `gestureShape` put through the same snapping: a *reveal* preview is drawn inside the fog layer with `destination-out` (`MapStage`'s `fogOverlay` prop), so the DM sees the map appear under the brush as they drag without the mask being touched; a *hide* preview is a red tint in the overlay layer; the brush also shows its footprint under the pointer. The tool stays on for the next gesture; Esc abandons a gesture in progress or leaves the tool. The canvas surface reports `data-fogging` (mode or `false`), `data-fog-tool` and `data-fog-gesture` (`dragging` | `idle`). Completed shapes go to `FogActions.reveal` / `hide` with the feather width (`fogFeatherPx(cellSize)` = 30 % of a cell, 4–64 px) when feathering applies, i.e. one `map/fog-op` per gesture — a brush stroke is committed on release, not streamed per pointer move (ADR 0012's advice; keeps the log short and makes one stroke one undo step). The DM canvas reads the map's fog base PNG from the database (`useAssetBlob`) and hands it to the stage as `fogBase`. Undo / redo is `state/fogHistory.ts` (below), created by `DmView` over `FogActions.apply`.
- Calibration (T006, ADR 0011): `CalibrationPanel` shows the display the player window reported, the cell unit (1 inch / 25 mm), the **overview** override, and the two ways to calibrate: **ruler** (puts the player on a ruler screen showing a white square; ±1/±10 buttons and a size field grow/shrink it; "It measures 1 inch: save") and **TV size** (diagonal + native resolution, prefilled from the display report). Saving goes through a `CalibrationSession` (`state/calibrationSession.ts`, created by `DmView`, injectable in tests) that persists per display and updates the store's `presentation`, which the sync layer pushes to the player.
- Player view control (T009, ADR 0014): `PlayerViewPanel` rotates the player view in quarter turns (**⟲ 90°** / **⟳ 90°**, `rotation-value`), recentres it (`recentre-player-view`), holds the **Show splash when switching maps** preference (`splash-on-switch`) and the splash image picker (`splash-file-input`, `clear-splash-image`, `splash-thumb`, `splash-error`; through `state/splashActions.ts`). `DmCanvas` always draws the **player viewport rectangle** in the stage's `controls` layer: the map area the player display shows, from `map/playerView.ts` (`resolvePlayerView` + `playerViewportRect` over `playerPresentation(store.presentation)`, the reported `playerDisplay`'s size — `DEFAULT_PLAYER_DISPLAY` 1920×1080 until a player has said hello — and the scene). A white bar marks the map edge that is at the top of the TV (`tvTopEdgePoints`), a label says whether it is the whole map. While the player scale is locked (`isScaleLocked`: calibrated and not overview) and no canvas tool runs, the rectangle (a Konva `Group`, no fill so the DM's pixels are untouched) is draggable: every drag move clamps the centre onto the map and calls `setPresentation({ center })`, which the sync layer forwards at once; with a tool running, or a fitted map, it is a dashed, inert outline. The surface reports `data-player-center`, `data-player-rect` (`x,y,w,h`, rounded), `data-player-rotation` and `data-player-draggable`.
- **Single source of truth is the DM window Zustand store.** The player window is a dumb mirror: it applies sync messages received over a BroadcastChannel and renders. It never mutates state. Message schema lives in app/src/state/sync.ts (typed, versioned). Full-state snapshot on player connect; deltas after (fog ops are sent as operations, never bitmaps). Binary assets (map images) are pushed by the DM as `asset` messages on the same channel (ADR 0008); the player never reads storage. How the player should present scenes on its display (calibration, overview, ruler screen — ADR 0011; pan centre, rotation, blackout, splash — ADR 0014) travels as an unsequenced `presentation` message; the player's `hello` carries its `DisplayInfo` so the DM can look up that display's calibration.

### State & sync modules (`app/src/state/`)
- `model.ts` — scene-level data model: `MapScene` (id, name, `imageAssetId | null`, `backgroundColor`, size, `grid`, fog: `fogMaskAssetId` (the base PNG, null = fully fogged) + `fogOps` (the op log) + `fogOpsFrom` (history index of `fogOps[0]`; ADR 0012), tokens, annotations), `GridSettings` = `GridGeometry` (`cellSize`, `offsetX`, `offsetY` in map pixels; any offset is legal, renderers wrap it into the first cell) + one `GridStyle` (`visible`, `color`, `opacity` 0..1) per `GridView` (`dm`, `player`; ADR 0010), `Token`, `Annotation`, `AssetId`, `AssetKind` (`map-image`, `token-image`, `fog-mask`, `splash-image`), `SCHEMA_VERSION` (6), plus structural type guards. Binary data is referenced by `AssetId`, never embedded.
- `fog.ts` — fog operations (ADR 0012, ADR 0013), pure and shared by both windows: `FogMode` (`reveal` | `hide`), `FogShape` (`rect` | `circle` | `polygon` (flat points, ≥ 3) | `stroke` (flat points ≥ 1 + `radius`: a brush drag, round caps and joins; one point is a disc) | `rects` (flat `[x, y, w, h, ...]`, a union of rectangles: what grid snapping produces), all in map pixels), `FogOp` (`{ type: "fill", mode }` | `{ type: "shape", mode, shape, feather? }` — `feather` is the soft-edge width in map px, only present when positive), constructors `fogFill`, `fogShape(mode, shape, feather?)`, `rectShape(a, b)` (any two corners → normalised rect), `strokeShape`, `polygonShape`, `rectsShape`, `fogShapeBounds`, `cloneFogOp`, and guards `isFogOp`/`isFogShape`.
- `shared.ts` — `SharedState` (the only state the player ever sees: `campaignName`, `maps`, `activeMapId`, `splashImageAssetId` (the campaign's splash image, null = title card; ADR 0014)) plus `SharedOp`, the discriminated union of operations that change it (`campaign/set-name`, `campaign/replace`, `campaign/set-splash-image` (`{ assetId | null }`), `map/add` (with optional insert index), `map/remove` (clears `activeMapId` if it pointed there), `map/rename`, `map/set-active` (ignored for unknown ids), `map/set-grid` (replaces a map's whole `GridSettings`; no-op for unknown ids or unchanged settings; `gridSettingsEqual`), `map/fog-op` (appends a copy of one `FogOp` to a map's log; earlier entries keep their identity), `map/fog-undo` (drops the last op of a map's log; no-op on an empty log or unknown id — ADR 0013), `map/fog-compact` (`{ id, baseAssetId, opCount }`: the first `opCount` ops are baked into `baseAssetId`, which becomes the base; they are dropped and `fogOpsFrom` advances; ignored when the log is shorter than `opCount`)), and the pure reducer `applyOp`. Both windows run the same reducer. `SharedState` is also the body of the persisted campaign document, so it must stay plain JSON. Later tasks extend the state and add op kinds here.
- `maps.ts` — pure scene helpers: `createImageMapScene`, `createBlankMapScene` (size in cells × cell size, colour; both fully fogged: null base, empty log), `duplicateMapScene` (deep copy, shares the immutable image asset, takes the id of a *copied* fog base, copies the fog log), `findMap`/`activeMap`, `sceneAssetIds`/`referencedAssetIds` (every map's assets plus the splash image), and `assetIdsForPlayer` (active map's assets first, then the splash image, then every other map's).
- `mapActions.ts` — the DM's map operations over a store + database: the import pipeline `importMapImage(db, campaignId, file, { measureImage })` (validate PNG/JPEG/WebP by MIME or extension → decode for size (`measureImageInBrowser`: `createImageBitmap`, `Image` fallback; injected in tests) → `putAsset` → `createImageMapScene`; throws `MapImportError`, writes nothing on failure) and `createMapActions(store, db)` → `importImage` (add + activate in one dispatch), `createBlank`, `duplicate` (copies the fog-mask Blob, inserts after the original, activates the copy), `rename`, `remove` (then deletes assets nothing references any more — image assets are shared by duplicates), `setActive`, `setGrid` (one `map/set-grid` op).
- `fogActions.ts` — the DM's fog operations over a store + database (ADR 0012): `createFogActions(store, db, { bake, compactAt?, keepOps?, newId?, onError? })` → `apply(mapId, op)` (one `map/fog-op`; nothing for unknown maps), `reveal`/`hide(mapId, shape, feather?)`, `revealAll`/`hideAll(mapId)`, `idle()` (tests: wait for compactions). **Compaction**: once a log has `FOG_COMPACT_AT` (64) ops, the first `length − FOG_KEEP_OPS` (32) are baked with the injected `bake` (browser: `map/fogMask.ts: bakeFogMask`) into a PNG, stored as a `fog-mask` asset, and dropped with one `map/fog-compact`; the baked prefix is re-verified against the live log after every await (aborts, storing nothing, if it changed), the previous base is deleted once unreferenced, one compaction runs per map at a time, and a failed one is reported via `onError` and retried on the next op. Off-limits to `src/player/**`.
- `fogHistory.ts` — fog undo / redo on the DM side (T008, ADR 0013): `createFogHistory(store, { apply?, maxRedo? })` → `undo(mapId)` (dispatches `map/fog-undo` and pushes the dropped op on a DM-only per-map redo stack; false with nothing to undo), `redo(mapId)` (pops the stack and re-appends the op through `apply`, default a plain `map/fog-op` dispatch; the DM view passes `FogActions.apply` so a redone op can trigger compaction), `canUndo` (log non-empty), `canRedo` / `redoDepth`, `subscribe` (redo stack changes; the panel uses `useSyncExternalStore`), `start()` (attaches the store listener that discards a map's redo stack on any *new* `map/fog-op` — not on redo's own — and on `map/remove` / `campaign/replace`; returns the stop function). The undo history *is* the log, so undo reaches back to `fogOpsFrom`: at least `FOG_KEEP_OPS` (32) steps after a compaction, unbounded before one; ops baked into the base are gone for good. Redo keeps `FOG_MAX_REDO` (100). Off-limits to `src/player/**`.
- `splashActions.ts` — the DM's splash image over a store + database (T009, ADR 0014): `createSplashActions(store, db, { newId? })` → `setImage(file)` (validates PNG/JPEG/WebP like map import, `putAsset` as `splash-image`, one `campaign/set-splash-image`; throws `MapImportError`, writes nothing on failure) and `clearImage()`; either deletes the previous image once nothing references it. Off-limits to `src/player/**`.
- `assetCodec.ts` — `blobToBase64` / `base64ToBlob` for `asset` messages.
- `rotation.ts` — `Rotation` (`0 | 90 | 180 | 270`, degrees clockwise on screen), `isRotation`, `normalizeRotation`, `rotateClockwise` / `rotateCounterClockwise`, `isQuarterTurn` (swaps width and height) and `mapEdgeAtTop` (which map edge lies along the top of the TV: a clockwise quarter turn brings the left edge up). Pure; shared by both windows (T009).
- `calibration.ts` — physical calibration, all pure (ADR 0011): `DisplayInfo` (`width`, `height` in CSS px, `pixelRatio`, `left`, `top`) + `readDisplayInfo(window)` + `displayKey` (the settings key, `WxH@dpr+left,top`); `CellUnit` (`inch` | `mm25`) and `cellInches`; `DisplayCalibration` (`pxPerInch` in CSS px, `method` `square` | `diagonal`, `updatedAt`); derivations `pxPerInchFromSquare(sizePx, unit)` and `pxPerInchFromDiagonal({ diagonalInches, widthPx, heightPx, pixelRatio })` (null outside 10–600 px/in); `lockedScale(pxPerInch, unit, cellSizePx)` = the player stage scale; `PlayerPresentation` (`{ pxPerInch | null, cellUnit, overview, target, rotation, center: MapPoint | null, blackout, splash }`, what the `presentation` message carries; T009 added the last four — `center` is the map point at the middle of the player display, null = the map's centre) with `presentationMode` → `calibrating` | `calibrated` | `overview` | `uncalibrated` (blackout and splash are overlays, not modes), `isPlayerPresentation`, `playerPresentationEqual` (centre by value), `clonePlayerPresentation`; `PresentationState` (the DM-only store slice: `playerDisplay`, `calibration`, `cellUnit`, `overview`, `target`, `rotation`, `center`, `blackout`, `splash`, plus the DM-only preference `splashOnSwitch`), `playerPresentation(state)` and `presentationForMapSwitch(state, nextActiveMapId)` (drops the centre; raises the splash when `splashOnSwitch` and a map is being shown).
- `calibrationSession.ts` — DM-side plumbing over a store + database: `createCalibrationSession(store, db)` → `start()` (loads the cell unit; loads a display's calibration whenever `presentation.playerDisplay` changes, dropping stale loads), `save(calibration)` / `clear()` (persist for the connected display, then apply; false when no display is known), `setCellUnit`. Off-limits to `src/player/**`.
- `store.ts` — the DM store (`createTableStore`, app-wide `tableStore`, `useTableStore` hook). Shared state changes only via `dispatch(...ops)`, which applies the reducer, bumps `seq` by one per dispatch and notifies `onOps` listeners. `campaignId` (DM-only) names the persisted document the shared state belongs to; `openCampaign(campaign)` sets it and applies `campaign/replace` in one commit, `closeCampaign()` clears it. `presentation` (DM-only, `PresentationState`) changes via `setPresentation(patch)` and `setPlayerDisplay(display)` (a different display drops the loaded calibration); neither bumps `seq`. A dispatch whose ops change `activeMapId` also applies `presentationForMapSwitch` in the same commit (the pan centre belongs to the active map; T009), before op listeners run. **`src/player/**` may not import this module** (ESLint `no-restricted-imports` + `boundary.test.ts`).
- `sync.ts` — the protocol (ADR 0006, ADR 0008, ADR 0011): `PROTOCOL_VERSION`, `SYNC_CHANNEL_NAME`, message types `hello` (optionally with the player's `display`) / `snapshot` / `delta` / `asset` (`{ id, kind, mime, data: base64 }`, unsequenced) / `presentation` (`PlayerPresentation`, unsequenced, latest wins), constructors, `encodeMessage` (JSON string) and `decodeMessage`/`validateMessage` (never throw; reject other versions, unknown types and bad shapes).
- `transport.ts` — `SyncTransport` interface (`post`, `onMessage`, `close`). `createBroadcastTransport` wraps a BroadcastChannel; `createMemoryHub` is the in-test replacement with the same fan-out (never echoes to the sender); `createNullTransport` is used where BroadcastChannel is missing.
- `mirror.ts` — the player-side `MirrorState` (`connecting | synced`, `seq`, `shared | null`, `assets: Record<AssetId, Blob>`, `presentation: PlayerPresentation`) and the pure `reduceMirror(mirror, message)`: snapshots always replace; a delta applies only if `seq === mirror.seq + 1`; stale/duplicate deltas are ignored; a gap, or a delta before any snapshot, sets `resync` so the caller re-requests a snapshot — as does a **DM** `hello`, so a restarted DM learns this player's display. `asset` messages are decoded into `assets` whenever they arrive (undecodable data is ignored); after every snapshot/delta, assets the state no longer references are dropped. `presentation` messages replace `presentation` (same object if identical); snapshots/deltas carry it through.
- `dmSync.ts` — `startDmSync(store, transport, { assets? })`: on start sends `hello(dm)` + a snapshot (so already-open players catch up) + the presentation, answers every player `hello` with a snapshot + presentation, forwards each dispatch as one `delta`, and sends a `presentation` whenever the store's `playerPresentation` changes. A player hello carrying a `display` is recorded with `setPlayerDisplay` (DM-only bookkeeping; the only thing a received message may write). Nothing received can mutate the *shared* state. With an `AssetSource` it also pushes every referenced asset not yet sent this session (queued, one at a time, `assetIdsForPlayer` order) after the snapshot/delta, and re-sends all of them on a `hello` from a client id it has not served yet (a known player re-announcing gets only the snapshot + presentation).
- `playerSync.ts` — `startPlayerSync(mirror, transport, { display? })` → `{ stop, announce }`: sends `hello(player, id, display?.())` on start, whenever `reduceMirror` asks for a resync, and on `announce()`; writes decoded messages into the mirror. **The player only ever sends `hello`.**
- React bindings: `dm/useDmSync.ts` (DM view; passes an `AssetSource` backed by `getAsset`) and `player/usePlayerSync.ts` (player view) create the transport inside an effect so StrictMode's double mount gets a fresh channel; both views accept an injected `createTransport` for tests. `usePlayerSync` also takes a `readDisplay` (default: `window.screen`, undefined where it is unknown, e.g. jsdom) and re-announces when the display key changes — checked on `resize` and every `DISPLAY_POLL_MS` (1 s), because the popup opens on the laptop and is dragged to the TV afterwards. `PlayerView` exposes `data-sync-status` / `data-sync-seq` / `data-active-map-id` / `data-view-mode` / `data-rotation` / `data-view-center` / `data-blackout` / `data-splash` on its root for e2e assertions.
- Reconnect: a reloaded player window is simply a new endpoint; its `hello` fetches a full snapshot and deltas resume from that `seq`. A player opened before the DM stays `connecting` until the DM's start-up snapshot arrives; it then re-announces so the DM learns its display and sends the matching calibration.

### Persistence modules (`app/src/state/`, ADR 0007)
- `campaign.ts` — the persisted document `Campaign = { schemaVersion, id, name, createdAt, updatedAt, state: SharedState }`, `CampaignSummary` (what the manager lists), `newCampaign`, `isCampaign`, and `migrateCampaign` (never throws; brings older documents to `SCHEMA_VERSION`, reports `newer-schema` / `invalid`).
- `db.ts` — the Dexie database `TableMapDb` (`getDb()` is the app-wide instance; tests construct their own with a unique name). Tables: `campaigns` (documents, JSON only; indexed by `name`, `updatedAt`), `assets` (`{ id, campaignId, kind, blob }` — map images, token images, fog masks as Blobs), `settings` (key/value: last opened campaign; later, per-display calibration).
- `persistence.ts` — async functions over a `TableMapDb`: `listCampaigns`, `createCampaign`, `loadCampaign` (migrates; throws `CampaignLoadError` for corrupt/newer documents), `saveCampaign`, `saveCampaignState` (what autosave calls; false if the campaign was deleted meanwhile), `renameCampaign`, `deleteCampaign` (also deletes its assets and the last-opened pointer), `putAsset`/`getAsset`/`deleteAsset`/`listAssetIds`, `getLastCampaignId`/`setLastCampaignId`, `getDisplayCalibration`/`setDisplayCalibration` (settings row `calibration:<displayKey>`; null clears; unreadable rows read as null), `getCellUnit`/`setCellUnit` (settings row `cellUnit`, default `inch`), and `resolveStartupCampaign` (last opened → most recently updated → new "Untitled campaign"; unreadable documents are skipped).
- `autosave.ts` — `startAutosave(store, save, { debounceMs })`: subscribes to the DM store; any change to `shared` while `campaignId` is set schedules a write of the latest state after the debounce (default 400 ms); bursts coalesce; writes are serialised; opening another campaign or closing flushes first; `flush()`/`stop()` for unmount and `pagehide`. Pure logic, no IndexedDB.
- `session.ts` — `openStoredCampaign(store, db, id)` and `bootstrapCampaign(store, db)` (load-on-start; no-op when a campaign is already open; concurrent calls share one promise so StrictMode's double effect cannot create two default campaigns).
- `src/player/**` may not import `db`, `persistence`, `autosave`, `session`, `calibrationSession`, `fogActions`, `fogHistory` or `splashActions` either (same ESLint rule + boundary test): the player never touches storage or writes state.

## Rendering (`app/src/map/`, shared by both views; imports neither `dm/` nor the DM store)
- Konva stage with layers bottom-to-top: map image -> grid -> tokens -> annotations -> fog -> tool overlay.
- `MapStage.tsx` — the react-konva stage. Props: `scene`, decoded `image` (or null), container `size`, `viewport` (`{ x, y, scale, rotation? }` = stage transform; rotation in degrees clockwise, applied by Konva after the scale — the player view's quarter turns, T009), `gridView` (`dm` | `player`: which of the scene's two grid styles to draw and how opaque the fog is — the DM canvas passes `dm`, the player view `player`), `interactive` (wheel zooms around the pointer, dragging the stage pans; the new viewport is reported via `onViewportChange` — the caller owns it), `pointerTool` (`{ onDown, onMove, onUp }` receiving map-pixel points from the stage's mouse/touch events; while set, drag-pan is off but wheel zoom stays), `overlay` (Konva nodes drawn in a top layer, in map coordinates), `fogOverlay` (Konva nodes drawn inside the fog layer after the mask, in map coordinates — a node with `globalCompositeOperation="destination-out"` punches a live preview through the fog; T008), `controls` (Konva nodes in a *listening* layer above everything, in map coordinates — the DM's draggable player-viewport rectangle; a draggable node here takes the drag instead of the stage; T009), `fogBase` (the Blob of the scene's fog base PNG, undefined until available). Layer 1: a `Rect` in `scene.backgroundColor` (all of a blank map) under the `Image`; layer 2 (only if the chosen style is visible): the grid as one `Shape` (`strokeScaleEnabled=false` so lines stay 1 px at any zoom); layer 3 (always): the fog mask canvas as a Konva `Image` at `FOG_ALPHA[gridView]` (0.5 dm, 1 player); layer 4 (only with an overlay). The wrapper exposes `data-map-id`, `data-map-name`, `data-image-status` (`none | waiting | loading | loaded | error`), `data-scale`, `data-viewport-x` / `data-viewport-y` (the stage translation, so e2e can map map-pixel points to screen), `data-rotation`, `data-grid-view`, `data-grid-visible`, `data-tool`, `data-fog-status` (`ready | bridged | waiting`, see below), `data-fog-ops` (log length) and `data-fog-history` (`fogOpsFrom + log length`, the map's total fog op count — what e2e watches to time a reveal) for tests.
- `viewport.ts` — pure math: `fitToView` (contain + centre with padding), `centerAtScale` (dictated scale, map centred), `zoomAt` (keeps the map point under the pointer fixed; scale clamped to 0.05–8), `wheelZoomFactor`, `panBy`, `rotateVector` (clockwise, exact for quarter turns), `screenToMap`/`mapToScreen` (honour the viewport's `rotation`). `playerView.ts` (T009, ADR 0014) — how the player display shows a scene, shared by both windows: `PlayerView` = `{ center, scale, rotation }`; `resolvePlayerView(presentation, scene, display)` (scale = `lockedScale` while `isScaleLocked` — calibrated and not overview — else fit to the *rotated* display via `rotatedSize`; centre = the presentation's centre clamped onto the map (`clampCenter`) while locked, else the map's centre — a fitted map has nowhere to pan); `playerStageTransform(view, display)` → the stage `Viewport` that puts the centre mid-display, rotated (`display / 2 − rotate(center × scale)`); `playerViewportRect(view, display)` → the inverse: the axis-aligned map rectangle the display shows (`display / scale`, width and height swapped by a quarter turn, centred on `center`), which the DM drags; `rectCenter`; `DEFAULT_PLAYER_DISPLAY` (1920×1080). Rotation never changes the scale, so a calibrated cell is the same number of screen pixels whichever way the map is turned. `grid.ts` — `normalizeOffset`, `gridLinePositions`/`gridLines` from `GridGeometry` (offset wrapped into the first cell), and `alignGridToSquare(a, b)`: two opposite corners of one printed square (any order, either diagonal) → `{ cellSize, offsetX, offsetY }`; cell size is the mean of the box's width and height, offset is the box's top-left wrapped into the first cell; null below `MIN_ALIGN_CELL_SIZE` (4 px). `alignment.ts` — the alignment tool's pure state machine (`reduceAlignment(state, event)`: `idle` → `dragging` on press; release after ≥ `minDrag` completes, a shorter release is a click and moves to `second`, where the next press completes; `cancel` from anywhere; `alignmentBox` gives the preview rectangle). `minDrag` is `ALIGN_CLICK_THRESHOLD_PX` (6 screen px) divided by the viewport scale.
- `useImageElement.ts` — Blob → object URL → decoded `HTMLImageElement` (revoked on change/unmount). `useContainerSize.ts` — ResizeObserver-backed element size.
- DM (`dm/DmCanvas.tsx`): reads the active map's image Blob and fog base Blob from the database (`dm/useAssetBlob.ts`, which also provides object URLs for the panel thumbnails), fits the viewport whenever the active scene changes, then leaves pan/zoom to the user. Player (`PlayerView`): takes both Blobs from the mirror's `assets`, shows the idle campaign title when no map is active, and picks its viewport from the mirror's `presentation` (see Calibration below).
- Fog (T007, ADR 0012): the mask is an offscreen canvas the size of the map, derived from the scene's base PNG + op log, never received as pixels while editing. `fogRaster.ts` — `FogRaster<Base>` (`reset(base | null)`, `fillAll`, `fillRect`, `fillRects`, `fillCircle`, `fillPolygon`, `fillStroke`, each with a `FogMode` and an optional `feather`) and `applyFogOp(s)`, the single place that turns a `FogOp` into raster calls; two implementations: `createCanvasFogRaster` (production: `hide` = `source-over` black, `reveal` = `destination-out`; polygons even-odd, rect unions one non-zero path, strokes a round-capped/joined `stroke()` of `lineWidth = 2 × radius`; a feathered op is painted as its own blurred shadow — the shape drawn `SHADOW_SHIFT` (65536) px off the canvas with `shadowOffsetX` bringing the shadow, blurred by `shadowBlur = feather`, back into place; works with both composite operations in every browser, unlike `ctx.filter`) and `createBitmapFogRaster` (a `Uint8Array` alpha, 255 hidden / 0 revealed, pixel-centre coverage, strokes as capsules per segment, feather ignored — the hard edge is where a feathered edge crosses 50 %; `isHidden(x, y)`, `hiddenFraction()` — the unit-test double and, later, the "token under fog" query). `geometry.ts` — pure point / segment / rectangle / polygon containment, distance and intersection helpers. `fogSnap.ts` — `snapShapeToCells(shape, grid, map)`: the grid cells a shape touches (positive-area overlap with the cell shrunk by `SNAP_EPSILON` = 0.001 px, so an edge on a grid line does not spill into the neighbour), clipped to the map, runs per row merged, as one `rects` shape or null. `fogGesture.ts` — the fog tools' pointer state machine (see the DM layout section). `fogMask.ts` — `createFogMaskUpdater(raster)`: `update(scene, base)` returns `ready` (incremental: only ops past the history index it has applied are drawn; or a rebuild from the base when the map, the base or the log's past changed), `bridged` (the base changed by compaction but its PNG has not arrived/decoded: the pixels are already right, so keep them, apply new ops, rebuild once it lands) or `waiting` (a base this window never had: fully fogged, the safe default); `bakeFogMask(scene, baseBlob, opCount)` renders base + prefix to a PNG Blob for compaction. `useFogMask.ts` — one canvas per stage, updated in a layout effect, with an `onDraw` callback that `batchDraw`s the Konva layer. DM composites the mask at 50 % alpha, player at 100 %. A brush drag never touches the mask until release: the in-progress stroke is a Konva node punched through the fog layer (`fogOverlay`), so dragging costs one overlay redraw per frame whatever the map size, and the committed op is one `fillStroke` on the mask (about 2 ms on a 4096 × 2048 mask in headless Chromium, see `backlog/T008.md`).
- Calibration (T006, ADR 0011): the player view's mode is `presentationMode(presentation)`. **calibrated** — stage scale locked to `lockedScale(pxPerInch, cellUnit, scene.grid.cellSize)` so one cell is `pxPerInch * cellInches` CSS px whatever the image resolution, centred on the DM's pan centre (`resolvePlayerView` + `playerStageTransform`; the map's centre until the DM drags the viewport rectangle). **overview** — the DM's override: fit to window plus a "not to scale" badge (`data-testid="player-overview-badge"`). **uncalibrated** — fit to window. **calibrating** — the ruler screen: a plain `div` square of exactly `target` CSS px (`data-testid="calibration-target"`, `data-size-px`) with the unit label, instead of the map. Konva and the DOM both draw in CSS px, so the square and a calibrated cell agree at any device pixel ratio. The DM stage keeps free pan/zoom.
- Player view control (T009, ADR 0014): the stage is rotated by `presentation.rotation` (a `Viewport.rotation`; fitted maps are fitted to the rotated window, so a quarter turn fits the map's width to the window's height). The idle title and the splash content are wrapped in a `Rotated` box (CSS `transform: rotate(...)`, width and height swapped for a quarter turn) so text reads the right way up for the players. **Blackout** (`presentation.blackout`) is an opaque black `div` over everything (`data-testid="player-blackout"`, z-index 20); **splash** (`presentation.splash`) is a black `div` over the scene (`player-splash`, z-index 10, `data-splash-kind` `image` | `title`) showing the campaign's splash image (`player-splash-image`, from the mirror's asset for `splashImageAssetId`, object-fit contain; the title until it has arrived) or the campaign name (`player-splash-title`). Both are DOM layers, not stage changes: they appear the instant the message lands and the stage underneath keeps its fog mask warm for when they lift. Priority, top down: blackout > ruler screen (replaces the scene and hides the splash) > splash > scene / idle title.

## Storage
- Dexie (IndexedDB), database `tablemap`: `campaigns` (one JSON document per campaign = metadata + `SharedState`), `assets` (map images, fog-mask PNGs, token images as Blobs, keyed by `AssetId` and owned by a `campaignId`), `settings` (last opened campaign; per-display calibration under `calibration:<displayKey>`; the `cellUnit` preference — ADR 0011). Blobs are never serialised into the document; documents reference them by id. See ADR 0007. Calibration is deliberately *not* in the campaign document: it belongs to the TV, applies to every campaign, and must not travel in exports.
- Autosave is a debounced subscription on the DM store (`state/autosave.ts`), started by the `/dm` route and flushed on unmount / `pagehide`. Load-on-start opens the last campaign (or creates "Untitled campaign").
- Every document carries `schemaVersion` (currently 6: v1 → v2 adds `MapScene.backgroundColor`, ADR 0009; v2 → v3 turns the single grid style into `grid.dm` + `grid.player`, ADR 0010; v3 → v4 adds the fog log `fogOps` + `fogOpsFrom`, ADR 0012; v4 → v5 changes no data — the fog op vocabulary grew (`stroke`, `rects`, `feather`), so v4 builds must refuse v5 documents rather than call them invalid, ADR 0013; v5 → v6 adds `SharedState.splashImageAssetId` (null), ADR 0014); `migrateCampaign` runs the `MIGRATION_STEPS` chain forward on load and refuses newer documents. Dexie `version(n)` is only bumped for index changes.
- Map images are written once at import (`putAsset`, kind `map-image`) and referenced by `MapScene.imageAssetId`; duplicating a map shares the image, so an asset is deleted only when the last map referencing it is removed (`mapActions.remove`).
- Fog masks (kind `fog-mask`, PNG) are written by compaction of a map's fog log (`fogActions`, ADR 0012) and referenced by `MapScene.fogMaskAssetId`; the previous base is deleted once nothing references it. A map's fog therefore persists as the base PNG plus the ops since it in the document; a map that has never been compacted has only the ops. Duplicating a map copies the base Blob under a new id.
- The splash image (kind `splash-image`) is written by `splashActions.setImage` and referenced by `SharedState.splashImageAssetId`; choosing another or clearing it deletes the old one unless something else references it. The player view's pan centre, rotation, blackout and splash state are session-only presentation (ADR 0014): not in the document, not in settings.
- Export/import: JSZip bundle — campaign.json (the same document) + assets/ blobs. Importers run the same migration.
