## Goal
A pure, well-tested module that computes what a point sees: the visibility polygon from an origin against wall segments, limited to a radius, with closed doors blocking and open doors not. No UI, no store changes. Plan: `docs/plans/2026-09-v2-vision-and-depth.md` §2.

## Design
- `map/visibility.ts`:
  - `blockingSegments(walls: readonly WallSegment[]): Segment[]` — walls plus closed doors.
  - `visibilityPolygon(origin: Point, radiusPx: number, segments: readonly Segment[], bounds: Size): number[]` — flat `[x0, y0, …]` polygon in map pixels. Standard angular-sweep raycast: cast rays to every segment endpoint (±ε angle) plus rays to the radius circle at fixed angular steps (`RADIUS_STEPS`, 64), nearest hit per ray (segment intersection or the radius circle), sorted by angle. The map bounds are four implicit segments so rays always hit something. Degenerate inputs (origin on a segment, zero radius, no segments) return a sane polygon and never throw.
  - `visionRadiusPx(visionCells: number, cellSize: number)`.
  - `polygonUnionArea` is **not** needed; the overlay (T107) draws the polygons one by one.
- Performance budget, asserted by a test: 400 blocking segments, one origin, **< 4 ms** on Node in the test run (loose enough for CI, tight enough to catch an O(n²) mistake).
- The origin is a token's *centre*; that mapping lives in T106, not here.

## Acceptance criteria
- [ ] In an empty map the polygon is the radius circle (area within 2 % of πr²)
- [ ] A closed door blocks and an open door does not; a wall casts a correct shadow (sampled points inside/outside match a brute-force point-visibility check)
- [ ] Budget test passes; no `any`; no DOM or Konva imports

## Test requirements
- Unit: `map/visibility.test.ts` — the criteria above, plus: origin exactly on an endpoint, collinear segments, segments outside the radius are ignored, bounds clipping, determinism (same input → identical output).
- Docs: architecture (module + algorithm summary), ADR 0025 "Visibility by angular sweep; committed as ordinary reveal ops" (written here, finished by T106).
