## Goal
Replace the single scrolling DM sidebar with five tabs grouped by phase of use, and put the armed tool in the toolbar so it is visible whatever tab is open. Design and rationale: `docs/plans/2026-09-dm-usability.md` §1–§2, §3.2. No store or protocol changes.

## Design
- Tabs (in this order, `data-testid="dm-tab-<id>"`, ids `maps | fog | tokens | draw | table`):
  - **Maps**: campaign name, `MapPanel` (list, import, blank map), `GridPanel`.
  - **Fog**: `FogPanel`. **Tokens**: `TokenPanel`. **Draw**: `AnnotationPanel` (drawings + notes).
  - **Table**: `CalibrationPanel`, `PlayerViewPanel`.
- `dm/SidebarTabs.tsx`: `role="tablist"` / `role="tab"` (`aria-selected`, `aria-controls`), Left/Right arrow keys move between tabs, the panel is `role="tabpanel"` `data-testid="dm-tabpanel"` `data-tab="<id>"`. Inactive panels are unmounted. The chosen tab is remembered in `localStorage` (`tablemap.dm.tab`); default **Maps**. Transient form drafts inside panels may reset on a switch; tool settings must not (they already live in `DmView`/the store).
- Switching tabs never disarms a tool.
- Toolbar **tool status chip** (`data-testid="tool-status"`): shown only while a tool is armed, with the tool's name and mode ("Align grid", "Fog · reveal brush", "Fog · hide rectangle", "Draw · pen", "Draw · eraser", "Place note"), a **Stop** button (`data-testid="tool-stop"`, same effect as Esc) and a click on the name that opens the owning tab. Pure `dm/toolStatus.ts` (`describeTool(tool, fogSettings, drawSettings) → { label, tab }`) so it is unit-testable.
- Toolbar keeps player window controls, blackout, splash and status unchanged (they must be reachable from every tab). Existing testids and labels on the panels are unchanged.

## Acceptance criteria
- [ ] All existing panel controls reachable through the tabs; nothing scrolls off on a 768 px-tall window with the Fog tab open
- [ ] Arming a fog brush, switching to Tokens, editing a token, switching back: the brush is still armed and the chip said so throughout
- [ ] Reload restores the last tab; a fresh browser opens on Maps
- [ ] All existing e2e specs green after adopting a shared `openTab(page, id)` helper (`e2e/helpers.ts`); no test weakened

## Test requirements
- Unit: `dm/SidebarTabs.test.tsx` (roles, arrow keys, persistence with a fake storage), `dm/toolStatus.test.ts` (every tool/mode → label + tab), `dm/DmView.test.tsx` (tool survives a tab switch; chip appears/stops; panels mount per tab). Update the panel tests that go through `DmView` to open their tab first (one helper in `src/test/`).
- E2E: new `e2e/sidebar.spec.ts` (tabs, chip, persistence across reload); mechanical `openTab` updates in `fog`, `annotations`, `calibration`, `maps`, `player-view`, `persistence`, `session`, `sync` specs.
- Docs: user guide (every "under **Tools**" / section reference becomes a tab name; the keyboard/mouse table; screenshots-in-words in the quick start), architecture "DM view" paragraph, ADR 0020 (tabs + chip; why blackout/splash stay in the toolbar; why tabs never disarm tools).
