## Goal
A **Turns** tab in the DM sidebar to run combat: add entries (typed, or from the active map's tokens), set values, sort, advance turns and rounds, and see whose turn it is. Plan: `docs/plans/2026-09-v2-vision-and-depth.md`.

## Design
- Tab `dm-tab-turns` after Tokens (T016 `SidebarTabs`; T018 shortcut `7`, or the next free digit — record the mapping in Notes). Panel `dm/InitiativePanel.tsx` (`initiative-panel`).
- Controls: **Add** form (`initiative-name`, `initiative-value`, submit `initiative-add`); **Add from token** select listing the active map's tokens by label (`initiative-add-token`; the entry takes the token's name and links it); list (`initiative-item`, current one `data-current="true"`): editable value (`initiative-item-value`), name, link indicator, remove (`initiative-item-remove`), click a row to make it current; **Sort** (`initiative-sort`), **Prev** / **Next** (`initiative-prev` / `initiative-next`), **Round n** (`initiative-round`), **Reset** and **Clear** (inline confirm).
- DM canvas: the current entry's linked token, if on the active map, gets a highlight ring in the controls layer (`data-testid="turn-ring"`); the ring is DM chrome here, the player's ring is T111.
- Keyboard: `Space`? No — Space is the pan override (T018). Use `.` next and `,` prev when the Turns tab is open and focus is not in a field.

## Acceptance criteria
- [ ] Five entries: add, sort, next through a full round (round counter increments), remove the current one, clear
- [ ] Adding from a token links it and the ring follows the current turn on the DM canvas
- [ ] All state changes are ops (no local state except the add-form draft)

## Test requirements
- Unit: `dm/InitiativePanel.test.tsx` (every control dispatches the right op; current row attribute), `dm/DmView.test.tsx` (tab, keys, ring node when linked).
- Docs: user guide new §"Running initiative", keyboard table, architecture (tab, panel), ADR 0026 amended.
