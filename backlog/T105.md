## Goal
The data for vision, without the behaviour: each token gets a vision radius in cells, each map a dim override. Schema **v10**. Plan: `docs/plans/2026-09-v2-vision-and-depth.md` §1.

## Design
- `Token.vision: number` — whole cells, ≥ 0, default 0 (= no vision). Added to `TOKEN_FIELD_GUARDS` so `map/token-update` patches carry it; hidden tokens keep their vision (they still see; the DM decides what is revealed).
- `MapScene.visionDim: "auto" | "on" | "off"`, default `"auto"`. Op `map/set-vision-dim { id, visionDim }`. Meaning (used by T107): `auto` = dim revealed-but-unseen areas on the player while any token on the map has `vision > 0`; `on`/`off` force it.
- Migration v9→v10 adds both defaults. Archive round-trips them.
- Pure helper `state/vision.ts`: `seeingTokens(scene)` (vision > 0), `mapUsesVision(scene)` (`visionDim` resolved), `tokenCentre(token, cellSize)`.
- UI: token editor gains **Vision (cells)** (`token-vision`, number input 0–60, step 1); Fog tab gains **Dim unseen areas on the TV: Auto / On / Off** (`vision-dim`, a select). Both are wired to the ops; no rendering change yet.

## Acceptance criteria
- [ ] Setting a token's vision persists, syncs and survives export/import; a v9 document loads with `vision: 0` and `visionDim: "auto"`
- [ ] `mapUsesVision` is true for `auto` only when a token has vision, always for `on`, never for `off`

## Test requirements
- Unit: `model.test.ts` (guards, patch guard rejects negative/non-integer), `shared.test.ts` (op), `campaign.test.ts` (v9→v10), `campaignArchive.test.ts`, `state/vision.test.ts`, `dm/TokenPanel.test.tsx` and `dm/FogPanel.test.tsx` (controls dispatch).
