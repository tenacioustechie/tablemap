## Goal
On a map that uses vision, revealed areas no token currently sees are dimmed on the player screen (and lightly on the DM canvas); what the tokens see right now is bright. Derived in both windows from the same shared data; nothing new is stored or synced. Plan: `docs/plans/2026-09-v2-vision-and-depth.md` §2.

## Design
- Pure `map/visibleArea.ts`: `visiblePolygons(scene)` = `visibilityPolygon` per seeing token (respecting doors); memoised on `(walls, seeing tokens' positions/vision, cellSize)` so an unrelated fog op does not recompute it. `dimActive(scene)` = `mapUsesVision(scene)` (T105).
- Rendering (`MapStage`, both views): a **dim layer** above the fog layer and below tokens: a full-scene rect at the dim colour with the visible polygons cut out (`globalCompositeOperation: "destination-out"` within a cached group, or a `Shape` with even-odd holes). Dim strength per view: player 0.6 black, DM 0.25 black. The fog layer still hides unrevealed pixels fully on the player, so dim only ever affects revealed pixels. The layer is absent when `dimActive` is false — manual-fog maps render exactly as before (pixel-identical; assert in e2e).
- Tokens standing in a dimmed area stay drawn on the player (they are on revealed ground); the existing fogged-cell rule is unchanged.
- The stage exposes `data-dim="true|false"` for tests.

## Acceptance criteria
- [ ] Map with no seeing tokens (`auto`): no dim layer, pixels identical to pre-v2 output
- [ ] One seeing token: its polygon is bright, the rest of the revealed area is dimmed on the player; `visionDim: off` removes the dim, `on` forces it
- [ ] Moving the token (drop) moves the bright area; opening a door widens it without a new reveal
- [ ] No visible frame drop while dragging a token on a 400-segment map (preview + overlay recompute at most once per frame)

## Test requirements
- Unit: `map/visibleArea.test.ts` (memoisation, doors, no seeing tokens → empty), `map/MapStage.test.tsx` (dim layer present/absent, per-view opacity), `player/usePlayerSync.test.tsx` (`data-dim` follows a token-update delta).
- E2E: extend `e2e/vision.spec.ts` — player pixel sampling: bright inside the polygon, dimmed (darker than map colour, lighter than black) outside it, unchanged on a manual-fog map.
- Docs: user guide §4 "What the players see with vision on", architecture (layer order), ADR 0025 amended (overlay derived, not stored).
