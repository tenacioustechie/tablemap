## Goal
Ship `app/src/assets/splash-default.png` (already in place, 1672×941) as the splash the player screen shows when the campaign has no splash image of its own, instead of the plain campaign-title card. The title card stays available as an explicit choice. Design: `docs/plans/2026-09-dm-usability.md` §3.1.

## Design
- Schema **v7**: `SharedState.splashTitleCard: boolean` (migration v6→v7 adds `false`); op `campaign/set-splash-title-card { on }`; guard + `sharedStateForPlayer` carry it; export/import round-trips it.
- Player precedence: `splashImageAssetId` set → that image (title card as the placeholder until the asset arrives, as today) → else `splashTitleCard` → title → else the default artwork. `data-splash-kind` gains `"default"`; the artwork renders like a custom image (object-fit contain on black, inside `Rotated`).
- The artwork is a static asset imported by URL (`import defaultSplashUrl from "../assets/splash-default.png"`) from shared/player code. Never through the database or the asset channel: the player stays render-only and both windows load it from the same origin. Vite bundles it (`npm run build` must include it in `dist/assets/`).
- DM `PlayerViewPanel`: a radio "When no splash image is chosen: Default artwork / Campaign title" (`data-testid="splash-source-default"` / `"splash-source-title"`) above the existing image picker; the thumbnail shows whatever is in effect (artwork, custom image, or a title placeholder).
- The idle screen (no active map) keeps showing the campaign title — assumption; record it in Notes if kept.

## Acceptance criteria
- [ ] New campaign, "Show splash": player shows the default artwork (`data-splash-kind="default"`, image decoded)
- [ ] "Campaign title" selected → title card; a custom image chosen → that image; clearing it returns to whichever source is selected
- [ ] A v6 export imports with `splashTitleCard: false`; a v7 export round-trips byte-for-byte on the JSON
- [ ] `npm run build` emits the artwork; the player page loads it from the built site (check in `e2e` against the dev server is enough for the automated gate)

## Test requirements
- Unit: `shared.test.ts` (op + guard), `campaign.test.ts` (v6→v7), `mirror.test.ts`/`sync.test.ts` (field crosses the channel), `player/usePlayerSync.test.tsx` (three kinds, fake `Image`), `dm/PlayerViewPanel.test.tsx` (radio, thumbnail).
- E2E: extend the splash test in `e2e/player-view.spec.ts` with the default kind (image decoded, `naturalWidth` 1672) and the title-card choice.
- Docs: user guide §5 "Splash", architecture (schema history, player view control, storage), ADR 0019 amending ADR 0014 ("default artwork; title card is a choice").
