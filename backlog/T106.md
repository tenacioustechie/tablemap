## Goal
A token with vision reveals what it sees: the DM canvas previews the visibility polygon while the token is dragged, and one reveal op is committed when it is dropped. Door toggles and vision edits re-run it. Plan: `docs/plans/2026-09-v2-vision-and-depth.md` §2, ADR 0025.

## Design
- `state/visionActions.ts` — `createVisionActions(store)`: `revealFor(mapId, tokenId)` computes the polygon (`visibilityPolygon` from the token centre, `visionRadiusPx`, `blockingSegments(scene.walls)`) and dispatches one `map/fog-op` `polygon` reveal with the standard feather; `revealAll(mapId)` does it for every seeing token **in one `dispatch(...ops)` call** (one seq, one undo step, one delta).
- Triggers, all on the DM side only (the player never dispatches):
  - token drop (`tokens.move` completes) for that token, if `vision > 0`;
  - `map/token-update` that changes `vision` to > 0, for that token;
  - `map/door-set-open` (either direction) → `revealAll` for the map. Closing a door never re-hides anything (fog is additive; the guide says so).
  - Not on map switch, not on load (the log already holds what was seen).
- Feedback loop guard: the actions subscribe through `store.onOps` and must ignore the fog ops they dispatch themselves.
- Live preview: while a seeing token is dragged, `DmCanvas` draws the polygon for the pointer position in the overlay (same visual as the fog reveal preview, recomputed per pointer move, throttled to animation frames). Nothing is dispatched until drop.
- Fog undo (`history.undo`) removes the committed reveal like any other op.
- Perf: a drop with 400 segments must not visibly stall (the T104 budget covers the maths; the preview runs at most once per frame).

## Acceptance criteria
- [ ] Drop a vision-6 token in a walled room: exactly that room (minus the door's far side while closed) is revealed on DM and player; Ctrl+Z undoes it
- [ ] Open the door: the token's view widens on the next drop *and* immediately (door toggle re-runs vision); close it: nothing is re-hidden
- [ ] Dragging shows the polygon preview on the DM canvas and dispatches nothing until release; a token with vision 0 shows no preview and reveals nothing
- [ ] Two seeing tokens + one door toggle = one dispatch, one undo step

## Test requirements
- Unit: `state/visionActions.test.ts` (each trigger, single dispatch, no self-trigger loop, vision 0 ignored, closed vs open door), `dm/DmView.test.tsx` (drop → reveal op through injected actions), `map/MapStage.test.tsx` or `dm/DmCanvas` test for the preview node.
- E2E: `e2e/vision.spec.ts` — draw a room with a door (helpers from `walls.spec.ts`), add a token, set vision, drag it in by mouse: player pixel inside the room is map-coloured, outside the room black; toggle the door and check a pixel beyond it after a second drop; undo.
- Docs: user guide §4 "Vision: tokens that see", architecture, ADR 0025 completed.
