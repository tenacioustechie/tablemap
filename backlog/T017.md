## Goal
Let the DM turn a map (the document: image, grid, fog, tokens, annotations, all together) in 90° steps, independently of the player view's TV rotation (ADR 0014). A sideways scan gets fixed inside the app; the TV rotation keeps meaning "which way the TV faces". Design: `docs/plans/2026-09-dm-usability.md` §3.3.

## Design
- Schema **v8**: `MapScene.imageRotation: 0 | 90 | 180 | 270` (migration v7→v8 adds `0`). How far the stored image asset is drawn turned clockwise; `width`/`height` are always the *turned* size. The image asset is never re-encoded.
- `MapStage` draws the image with `rotation={imageRotation}` and the position/offset that makes the turned image cover `[0, width] × [0, height]` (image node width/height are the asset's own, i.e. swapped for a quarter turn). Both windows share this code.
- Op `map/rotate { id, degrees: 90 | 180 | 270, fogMaskAssetId: AssetId | null }` (clockwise). Reducer applies a pure `rotateScene(scene, degrees, fogMaskAssetId)` in new `state/sceneRotation.ts`:
  - quarter turn swaps `width`/`height`; `imageRotation` advances by `degrees` (normalised);
  - point transform for the old size (W, H): 90 → `(x, y) ↦ (H − y, x)`; 180 → `(W − x, H − y)`; 270 → `(y, W − x)`;
  - grid: `cellSize` unchanged, origin turned as a point and wrapped into the first cell — the set of grid lines of the turned scene must equal the turned set of lines (property test; note a turned vertical line becomes a horizontal one);
  - tokens: turn the footprint's centre, then top-left = centre − size·cell/2 (`x`/`y` for every token; sizes are square so nothing else changes);
  - annotations: note `x`/`y`; every drawing point;
  - fog ops: `rect`/`rects` corners turned and re-normalised, `circle` centre, `polygon`/`stroke` points (`radius`/`feather` unchanged), `fill` untouched; `fogOpsFrom` unchanged; `fogMaskAssetId` replaced by the op's.
- DM action `mapActions.rotate(id, degrees)`: cancel any armed tool; if the scene has a base mask, bake a turned copy on a canvas (`map/fogMask.ts: rotateFogMask`, same pattern as compaction) and `putAsset` it as a new `fog-mask`; dispatch; delete the old asset (only if nothing references it). The fog history's redo stack is cleared for that map (undo keeps working: the log's ops were turned in place).
- Store: a `map/rotate` on the *active* map drops `presentation.center` in the same commit (same mechanism as `presentationForMapSwitch`). `DmCanvas` refits when the scene's size changes, not only its id. The player's `useFogMask` must rebuild its canvas on a size change (verify; fix if it reuses the old one).
- UI (Maps tab, Grid section): "Map rotation" ⟲ / ⟳ with the current value (`data-testid="map-rotate-ccw"`, `"map-rotate-cw"`, `"map-rotation-value"`; aria-labels "Rotate map counter-clockwise/clockwise" — distinct from the "Rotate player view …" labels). Disabled while a fog bake is in flight.
- Export/import: the field travels in `campaign.json`; assets unchanged.

## Acceptance criteria
- [ ] Rotating a map turns image, grid, fog, tokens and notes together on both DM and player; the TV rotation is unaffected and still composes on top
- [ ] After a 90° turn on a map with a base mask and pending ops, a cell that was revealed is still revealed at its turned position; fog undo still works; redo is empty
- [ ] Rotate four times: scene deep-equals the original (fog mask pixels included)
- [ ] v7 documents load with `imageRotation: 0`; export/import round-trips a turned map
- [ ] Map rotation is a separate control from player view rotation; the user guide explains which to use when

## Test requirements
- Unit: `state/sceneRotation.test.ts` (point transform, 4×90 = identity, grid line-set property, tokens, annotations, every fog shape), `shared.test.ts` (op + guard), `campaign.test.ts` (v7→v8), `store.test.ts` (centre dropped on active-map rotate), `map/fogMask.test.ts` (`rotateFogMask` pixels), `map/MapStage.test.tsx` (image node rotation/position per value), `state/mapActions.test.ts` (bake + asset swap, redo cleared), `campaignArchive.test.ts` round-trip.
- E2E: new `e2e/rotation.spec.ts`: import the grid fixture, reveal one cell, rotate 90°; the DM surface reports the swapped scene size; a pixel sample at the turned cell is map-coloured on the player and the old position is black; then rotate the *player view* 90° and check `data-scale` unchanged (calibration preserved).
- Docs: user guide §2 ("Turning a sideways map") and §5 (difference from TV rotation), architecture (schema history, `sceneRotation.ts`, MapStage), ADR 0021 (rotation as a scene op; why the asset is not re-encoded; why redo is cleared).
