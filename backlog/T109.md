## Goal
The campaign-level initiative list as shared state with pure, tested ops; no UI yet (T110 DM tab, T111 player strip). Schema **v11**. Plan: `docs/plans/2026-09-v2-vision-and-depth.md` §1.

## Design
- `SharedState.initiative: Initiative` with `Initiative = { entries: InitiativeEntry[]; turn: number | null; round: number }`, `InitiativeEntry = { id; name: string; value: number; tokenId: string | null }` (`tokenId` refers to a token on any map; dangling ids are tolerated and treated as null by consumers). Default `{ entries: [], turn: null, round: 1 }`. Migration v10→v11 adds it. Archive round-trips it. Guards in `state/initiative.ts`.
- Ops: `initiative/add { entry }`, `initiative/update { id, patch }`, `initiative/remove { id }`, `initiative/sort` (by value desc, stable; keeps the current entry current), `initiative/next`, `initiative/prev` (wrap; `next` from the last entry bumps `round`; `prev` from the first decrements to a minimum of 1), `initiative/set-turn { id | null }`, `initiative/reset` (turn = first, round = 1), `initiative/clear`. Removing the current entry moves the turn to the next one (or null when empty). Removing a token (`map/token-remove`) unlinks entries that pointed at it.
- Everything goes to the player unfiltered (the strip needs it).
- Pure helpers: `currentEntry(initiative)`, `linkedToken(shared, entry)`.

## Acceptance criteria
- [ ] Every op behaves as specified on empty, one-entry and many-entry lists (wrap, round counting, removal of the current entry, token unlink)
- [ ] v10 documents load with the default; v11 round-trips through export/import
- [ ] Ops cross the channel and the mirror applies them

## Test requirements
- Unit: `state/initiative.test.ts` (guards + every op), `shared.test.ts` (token-remove unlink), `campaign.test.ts` (v10→v11), `campaignArchive.test.ts`, `sync.test.ts`/`mirror.test.ts`.
- Docs: architecture (model, ops, schema history), ADR 0026 "Initiative as campaign state; strip visibility as presentation" (started here, finished in T111).
